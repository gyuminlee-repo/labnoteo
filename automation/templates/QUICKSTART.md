# 연구노트 퀵스타트 (연구원용)

> 실험하는 연구원을 위한 문서입니다. 저장소 최초 설정(관리자용)은 `.labnoteo/SETUP.md`를 보세요.
>
> Git·GitHub 자동화를 쓰지 않는다면 [명령 찾는 법](#명령-찾는-법)·[기록하기](#기록하기)·[샘플 다루기](#샘플-다루기)만
> 보면 됩니다. 이 문서는 명령 팔레트 → `Open user guide`(사용법 열기)로 언제든 다시 열 수 있습니다.

**처음이라면 [5분 따라하기](#5분-따라하기)만 먼저 하세요.** 그 아래는 필요할 때 찾아보는 참조입니다.

## 이 보관함으로 하는 일

- Obsidian에서 쓰는 **노트가 곧 공식 연구 기록**입니다 (`labnote/` 폴더).
- 노트를 **push하면 자동으로**: 노트 형식이 검증되고, 논의가 필요한 실험은 GitHub Issue가 열립니다.
- 실험에서 확인된 사실은 **Wiki(논문형 초안)** 에 차곡차곡 쌓입니다.
- 커밋·푸시 같은 Git 작업은 **AI 에이전트에게 말로 시키면** 됩니다.

## 시작 전 확인 (1분)

- 관리자가 `.labnoteo/SETUP.md`의 최초 설정(GitHub 저장소 연결, 훅 활성화)을 마쳤는지
  확인하세요. (`.labnoteo/`는 숨김 폴더라 Obsidian 탐색기에는 보이지 않습니다 —
  탐색기 대신 파일 관리자나 에디터로 열어야 합니다.)
- 명령은 Obsidian **명령 팔레트**(Ctrl/Cmd+P)에서 찾습니다. 이름은 Obsidian의
  표시 언어를 따라가니, 한국어로 쓰고 있다면 `실험 생성`처럼 한글로 검색하세요
  ([대응표](#명령-찾는-법)). `Labnote`로 검색하면 언어와 상관없이 모입니다.
  언어를 바꿨다면 Obsidian을 다시 시작해야 명령 이름이 바뀝니다.

## 5분 따라하기

### 1. 실험 만들기

명령 팔레트 → **`Create experiment`** (실험 생성) → 실험 이름 입력.
`labnote/###_이름/README.labnote.md`가 생기고 바로 열립니다.
폴더 이름에서 공백은 `_`로, 하이픈·대시·물결(`–`, `~`)은 `-`로 바뀌고 그 밖의 기호는
빠집니다(예: `배지 최적화 (M1–M8)` → `001_배지_최적화_M1-M8`). 숫자 앞의 마이너스 부호는
남깁니다(예: `−80°C 보관` → `001_-80C_보관`). 숫자 사이의 소수점도 남고
(예: `OD600 0.4~0.8 수확` → `001_OD600_0.4-0.8_수확`), 숫자 사이의 다른 기호는 숫자가 서로
붙지 않게 바뀝니다. 곱셈기호 `×`는 `x`, 천 단위 쉼표는 빠지고(`2,500` → `2500`), 그 밖의
`/`·`:`·`±`·`,` 등은 `_`가 됩니다(예: `pH 7.0/8.0 비교` → `001_pH_7.0_8.0_비교`,
`3×2 요인 설계, 37±2` → `001_3x2_요인_설계_37_2`). 숫자 사이가 아닌 기호는 빠집니다
(예: `A/B 테스트` → `001_AB_테스트`). 제목 글자가 모두 기호나 이모지면 폴더 이름을 만들 수
없어 실험이 만들어지지 않습니다. frontmatter의 `title`에는 입력한 제목이 그대로 남습니다.

**열리자마자 frontmatter의 `author`를 채우세요.** 비워 두면 이 실험에서 이후 만드는
모든 워크플로·유닛 오퍼레이션의 `Experimenter`가 **경고 없이 빈 값**으로 들어갑니다.

README에는 목적(`Experiment Objective`)·관련 워크플로·요약을 기록합니다.

### 2. 진행 상태 바꾸기

명령 팔레트 → **`Change experiment status`** (실험 상태 변경) → 상태 선택
(`planned` → `in-progress` → `completed` / `failed` 등).

### 3. 기록하다 논의가 필요하면 그 자리에 표시하기

질문이 떠오른 문장을 선택하고 명령 팔레트 → **`Insert issue marker`**
(논의 이슈 마커 삽입). 이런 줄이 만들어집니다:

```markdown
3차 시도에서만 수율 40%. @issue;ISS-mkd8x3k;시드 배양 시간 차이 때문인지 논의 필요
```

`@issue;`부터 줄 끝까지가 한 마커이고, 뒤의 문장이 이슈 제목이 됩니다.
한 노트에 **여러 개**를 달 수 있고 각각 별도 이슈로 열립니다.
실험 폴더 안의 `README.labnote.md`든 워크플로 노트든 **어느 노트에 적어도 됩니다** —
실제로 질문은 대개 작업을 적는 워크플로 노트에서 나옵니다
([폴더 구조](#실험-폴더의-구조) 참고).
선택한 문장이 없으면 빈 마커가 들어가니 이어서 주제를 적으면 됩니다.

문장의 **일부만** 선택하거나 커서가 줄 중간에 있으면, 원문은 그대로 두고 마커를
**줄 끝에** 붙입니다(선택한 부분이 주제). 예: `BS-3 형광 높음 누출 의심`에서
`BS-3 형광`을 선택 → `BS-3 형광 높음 누출 의심 @issue;ISS-…;BS-3 형광`.
제목 줄에서 실행하면 제목 바로 아랫줄에 넣고, 표 안에서는 넣지 않습니다(표 아래 줄에서 실행).
이슈는 **`Setup research automation`(연구노트 자동화 설정)을 실행한 보관함**에서만
열립니다. 설정 전이면 명령이 그렇게 알려 줍니다.

`ISS-...`는 자동으로 붙는 식별자입니다. 이게 있어야 나중에 주제문장을 고쳐도
같은 이슈로 유지됩니다. **직접 짓지 마세요** — 명령이 만들어 줍니다.
마커가 색으로 강조되지 않는다면 형식이 잘못된 것이라 이슈가 열리지 않습니다.
같은 이유로 **마커가 있는 줄을 복사해 다른 노트에 붙여넣지 마세요** — ID가 따라가
두 질문이 한 이슈로 합쳐집니다. 복사했다면 그 줄의 마커를 지우고 새로 삽입하세요.

**실험 전체를 놓고 논의해야 한다면** 지점 마커 대신 명령 팔레트 →
**`Toggle discussion flag`**(논의 표시 전환)을 씁니다. 진행 상태(`status`)와는
별개라 `in-progress`인 채로 논의만 올릴 수 있습니다.

> 본문에 "논의 필요"라고 **쓰기만 해서는 이슈가 생기지 않습니다.** 마커나
> 논의 표시가 있어야 열립니다. 본문을 읽고 판단하게 하려면 AI 에이전트에게:
> *"이 실험 노트 읽고 논의가 필요해 보이면 표시해줘"*
> — 에이전트가 맥락을 판단해 (확인 후) 같은 표시를 남깁니다.

### 4. 커밋·푸시하기

AI 에이전트(Claude Code 등)에게 말하면 끝입니다:

> "오늘 작업 커밋하고 푸시해줘"

AI 에이전트(opencode / Claude Code / Codex)가 **Copilot에 연결되어 있어야** 합니다 — 에이전트를
고를 수 없거나 말해도 반응이 없으면 관리자에게 문의하세요(연결은 관리자용 설치 가이드 참고).
에이전트가 노트를 고치기 전에 보고 싶으면 입력창 아래 권한을 `Plan`으로 두세요(Claude).
기본 `Safe`는 노트 편집을 확인 없이 바로 적용할 수 있습니다.

에이전트는 이 보관함의 `AGENTS.md` 규칙에 따라 커밋 메시지를 자동 작성하고,
대용량 파일 검사를 통과한 뒤 push합니다. (직접 `git add / commit / push` 해도 됩니다.)

커밋할 때 노트 검증 경고가 뜰 수 있습니다. **커밋을 막지는 않지만**, 그대로 push하면
서버 검증이 같은 내용으로 실패하니 먼저 고치는 편이 낫습니다.

### 5. 이슈 자동 생성 확인하기

push하고 잠시 뒤, GitHub 저장소의 **Issues 탭**을 열어 보세요.

- `@issue` 마커마다 `[실험ID/ISS-...] 주제문장` 이슈가 열립니다. 본문에는 그
  마커가 있던 **노트의 정확한 줄로 가는 링크**가 들어 있어, 어떤 맥락에서 나온
  질문인지 바로 확인할 수 있습니다.
- 논의 표시(`discuss`)나 `status: needs-review`로 표시한 실험은 `[실험ID] 제목`
  이슈 하나가 열립니다. 이 이슈는 실험 전체의 논의 스레드라서, 닫았다가
  나중에 다시 표시하면 같은 이슈가 다시 열립니다.

(실험ID는 frontmatter의 `id`가 있으면 `EXP-###`, 없으면 폴더명 `###_이름`입니다.)

**바뀐 노트만 보는 게 아닙니다.** 자동화는 이번 push에서 바뀐 파일이 속한
**실험 폴더 전체**를 훑습니다. 예전 push 때 적어 두고 잊은 마커가 같은 폴더에
있었다면, 그 폴더의 아무 노트나 다시 고쳐 push하는 것만으로 함께 처리됩니다.

논의가 끝나면 GitHub에서 이슈를 닫으면 됩니다. 노트의 마커를 지워도 이슈는
닫히지 않고, 닫힌 마커 이슈가 다시 열리지도 않습니다.

> **작업 브랜치에 push해도 이슈는 열립니다.** 검증과 이슈 생성에는 브랜치 제한이
> 없습니다. 아직 논의를 올리고 싶지 않다면 마커를 나중에 넣으세요.

## Wiki에 결과 쌓기 (실험이 마무리되면)

1. AI 에이전트에게: *"이 실험에서 확인된 객관적 사실을 wiki-staging에 정리해줘"*
   — 에이전트가 `wiki-staging/`의 논문형 섹션(Methods, Results 등)에
   **사실 + 근거 실험ID**만 추가합니다 (해석·결론은 사람 몫).
2. 초안을 읽고 검토·수정합니다.
3. **`main`에 머지되어야** GitHub Wiki로 발행됩니다. 이슈와 달리 작업 브랜치에
   push하는 것만으로는 발행되지 않습니다.

## 명령 찾는 법

명령 팔레트(Ctrl/Cmd+P)에서 **`Labnote`** 를 치면 이 플러그인의 명령만 모입니다
(팔레트에는 `Labnote Assistant: ` 접두사가 붙습니다).

**이름은 Obsidian의 표시 언어를 따릅니다.** 한국어 UI면 한국어 이름으로,
영어 UI면 영어 이름으로 검색해야 합니다. 언어를 바꿨다면 Obsidian을 다시
시작해야 명령 이름이 바뀝니다.

| English | 한국어 |
| --- | --- |
| Create experiment | 실험 생성 |
| Change experiment status | 실험 상태 변경 |
| Insert issue marker | 논의 이슈 마커 삽입 |
| Toggle discussion flag | 논의 표시 전환 |
| Create workflow | 워크플로 생성 |
| Renumber workflows | 워크플로 번호 다시 매기기 |
| Sync workflow checklist with folder | 폴더와 워크플로 체크리스트 맞추기 |
| Insert unit operation | 유닛 오퍼레이션 삽입 |
| Insert date / Insert date and time | 날짜 삽입 / 날짜 및 시간 삽입 |
| Export tables to CSV | 표를 CSV로 내보내기 |
| Open workflow view / Open sample view | 워크플로 뷰 열기 / 샘플 뷰 열기 |
| Open user guide | 사용법 열기 |
| AI: Draft Method section | AI: Method 섹션 초안 작성 |
| AI: Summarize results | AI: 결과 요약 |
| AI: Extract sample definitions | AI: 샘플 정의 추출 |
| AI: Ask assistant (uses tools) | AI: 어시스턴트에게 요청 (툴 사용) |
| Setup research automation | 연구노트 자동화 설정 |

### 팔레트에 없는 기능 (우클릭 · 클릭 전용)

팔레트만 훑어서는 존재를 알 수 없는 것들입니다.

| 기능 | 어디서 | 하는 일 |
| --- | --- | --- |
| **Insert workflow** (워크플로 삽입) | `README.labnote.md` 편집 중 **우클릭** | 카탈로그에서 고른 워크플로 파일을 **새로** 만들고 이 README의 체크리스트에 등록. 이미 있는 파일(옮겨 오거나 복사한 것)을 등록하는 기능이 아닙니다 — 그때는 `Sync workflow checklist with folder`를 쓰세요. |
| **Go to definition** (정의로 이동) | 샘플 ID 위에서 **우클릭** | 그 샘플의 타입·별칭·설명·저장 파일을 팝업으로. 설정에서 **샘플 추적이 꺼져 있으면 메뉴 자체가 뜨지 않습니다.** 일반 `.md` 노트에서도 됩니다. |
| **날짜 선택기** | `#### Meta`의 `Start_date` / `End_date` **값을 클릭** | 달력·시계 피커. 값이 비어 있으면 줄 끝의 📅 아이콘을 누르세요. 읽기 모드에서는 동작하지 않습니다. |
| **표 CSV 내보내기** | 파일 탐색기에서 노트 **우클릭** | 팔레트 명령과 동일. |
| **리본 아이콘 2개** | 왼쪽 사이드바 | 상자 = 워크플로 뷰, 시험관 = 샘플 뷰. |

## 실험 폴더의 구조

`Create experiment`가 만드는 것과, 쓰다 보면 생기는 것:

```
labnote/
  001_Yield_optimization/
    README.labnote.md          ← 실험의 얼굴. 목적·워크플로 목록·요약
    001_WD010_General_Design_of_Experiment.labnote.md   ← 워크플로 노트
    002_WB020_Cloning.labnote.md
    images/                    ← 그림 넣는 곳
    resources/
      labsamples/              ← 이 실험에서만 쓰는 샘플 (DNA.json, Primer.json …)
resources/
  labsamples/                  ← 보관함 전체에서 공유하는 샘플
  workflows/                   ← 워크플로·유닛 오퍼레이션 카탈로그 (수정 가능)
```

**`@issue` 마커는 이 폴더 안 어느 `.labnote.md`에 적어도 됩니다.** 자동화는 폴더
전체를 훑기 때문입니다.

README frontmatter:

| 필드 | 뜻 | 기본값 |
| --- | --- | --- |
| `title` | 실험 제목 | 입력한 이름 |
| `author` | 실험자 | **빈 값 — 직접 채우세요** |
| `experiment_type` | `labnote`여야 검증·자동화 대상이 됩니다 | `labnote` |
| `sample_tracking` | 샘플 추적 사용 여부 | `yes` |
| `status` | 진행 상태 (`Change experiment status`로 변경) | `planned` |
| `project` | 상위 과제명 | 빈 값 |
| `created_date` | 만든 날 | 오늘 |
| `last_updated_date` | 마지막 기록일. 노트를 고치면 하루 한 번 자동으로 오늘이 됩니다(워크플로 노트를 고치거나 새 워크플로를 만들면 README도). 설정 → Labnote Assistant → 워크플로 → `마지막 갱신일 자동 기록`으로 끌 수 있습니다 | 오늘 |
| `id` | `EXP-###` 식별자 (선택). 없으면 폴더명이 실험ID | 없음 |
| `discuss` | 논의 표시 (`Toggle discussion flag`가 켜고 끕니다) | 없음 |

## 기록하기

### 워크플로 노트 (실험의 단계)

명령 팔레트 → **`Create workflow`** → 카탈로그에서 단계 선택 → 별칭 입력.
`002_WB020_Cloning_형질전환.labnote.md`처럼 **번호 + 카탈로그 코드 + 이름** 형식으로
만들어지고, README의 `## 🗂️ Related Workflows` 체크리스트에 자동 등록됩니다.

- 탐색기에서 **이름을 바꾸면** 번호 순서에 맞춰 README 체크리스트가 다시 정렬됩니다.
  탐색기 이름 칸에는 `.labnote`까지 보이니, 덧붙일 말은 `.labnote` **앞**에
  넣으세요(`001_WB030_Gibson v3.labnote.md`).
  체크리스트 라벨이 옛 파일 이름과 같았다면 라벨도 새 이름을 따라갑니다. 노트의 `title`과
  `## [ID 이름]` 제목도 옛 파일 이름과 같았다면 새 이름을 따라갑니다(파일 이름의 `_`는 공백으로
  들어갑니다). 직접 고친 라벨·title은 그대로 둡니다. 그 노트의 표 CSV(`노트이름.labnote_table1.csv`)도
  함께 옮겨집니다.
- 이름을 바꾸다 형식이 깨지면 경고와 함께 고칠 이름을 제안합니다. 제안을
  받아들이거나 직접 형식에 맞게 고치면 체크리스트가 다시 그 파일을 따라갑니다
  (Obsidian을 다시 시작하기 전에 고쳐야 합니다).
- **삭제하면** 체크리스트 항목이 사라집니다. 샘플은 그대로 남고, 그 노트의 사용 기록만 지워집니다.
- **다른 실험 폴더로 옮기면 README가 자동으로 갱신되지 않습니다.** 대신 "체크리스트에
  없습니다" 알림이 뜹니다. 대상 실험에서 `Sync workflow checklist with folder`
  (README나 실험 폴더 우클릭에도 있음)를 실행하면 옮겨 온 워크플로가 등록됩니다.
  원래 실험에서도 실행하면, 옮겨 간 항목을 보여 주고 확인을 받은 뒤 지웁니다.
  `Insert workflow`는 카탈로그에서 새 노트를 만드는 기능이라 옮긴 파일 등록에는 쓰지 마세요.
- 탐색기의 **"복사본 생성"** 으로 복제하면 `….labnote 1.md`처럼 형식이 깨진 이름이
  됩니다. 그러면 복제본의 **새 별칭**을 묻는 창이 뜹니다(원본 별칭이 채워져 있으니
  고쳐 쓰면 됩니다). 확인하면 다음 번호의 파일 이름, 노트의 `title`, `## [ID 이름]`
  제목이 새 별칭으로 바뀌고 체크리스트에 등록됩니다. 취소하면 아무것도 바뀌지 않고,
  나중에 직접 형식에 맞게 고쳐도 등록할지 묻습니다.
- `Renumber workflows`는 폴더의 워크플로 번호를 001부터 빈틈없이 다시 매기고,
  체크리스트에 없는 워크플로도 함께 등록해 폴더와 체크리스트를 맞춥니다.
  노트의 표 CSV도 새 번호로 함께 옮겨집니다(같은 이름의 파일이 이미 있으면 그 CSV는 두고 알려 줍니다).
- `Sync workflow checklist with folder`는 `title`·제목이 파일 이름과 어긋난 노트와, 라벨이
  파일 이름과 어긋난 항목도 찾습니다. 각각 `옛 이름 → 새 이름` 목록을 보여 주고 확인을 받은 뒤
  고칩니다.
- 파일명에서 `###_` 접두사나 `.labnote.md`를 지우면 **위 자동 동기화가 전부 멈춥니다.**
- **실험 폴더 이름도 `###_`로 시작해야 합니다**(예: `020_GFP`). 폴더 이름을 바꾸다 번호가
  빠지면 경고하고 옛 번호를 붙인 이름으로 되돌릴지 묻습니다. 번호 없는 폴더에서는 워크플로
  명령과 Local 샘플이 그 폴더를 실험으로 알아보지 못합니다.

### 유닛 오퍼레이션 (한 번의 작업)

**워크플로 노트를 연 상태에서** 명령 팔레트 → **`Insert unit operation`** →
카탈로그에서 장비/소프트웨어 작업 선택. README에서 실행하면
"워크플로 파일에서 실행해주세요" 경고만 뜨고 아무 일도 일어나지 않습니다.

커서 위치에 `### [UHW010 Liquid Handling]` 헤딩과 `#### Meta`(실험자·시작/종료 시각),
그리고 Input / Method / Output 같은 빈 섹션이 들어갑니다. 삽입 후 문서 맨 위
`## Related Unit Operations` 목차가 헤딩 순서대로 다시 만들어집니다. **유닛 오퍼레이션
블록을 옮기거나 지워도** 목차가 자동으로 다시 정렬됩니다(설정 → Labnote Assistant →
워크플로 → `유닛오퍼레이션 TOC 자동 정렬`, 기본 켜짐).
순서는 Obsidian **Outline** 보기에서 헤딩을 드래그해 바꿀 수 있으며, 목차와 `---` 구분선이 자동으로 정리됩니다. 다른 유닛 오퍼레이션 위에 놓으면 Outline은 그 아래 항목처럼 들여쓴 표시선을 보여 주지만, 블록은 쪼개지지 않고 그 유닛 오퍼레이션 블록 전체의 뒤로 들어갑니다. 정리는 이동과 별도로 저장되므로, 이동 전으로 되돌리려면 Ctrl+Z를 두 번 눌러야 할 수 있습니다.
목차 링크는 GitHub에서 노트를 볼 때 해당 블록으로 이동하는 용도입니다. Obsidian에서는 **Outline**(한국어 UI: 개요) 보기를 클릭해 이동하세요 — 같은 유닛 오퍼레이션이 여러 번 들어가도 각각 구분됩니다.

> **Input/Output vs 소모품 기록 규칙**: 다음 단계로 **샘플을 담아 넘기는** 플레이트·
> 시료는 `Input`/`Output`에(같은 플레이트 ID로 이어서 참조), 이 단계에서 **소모되는**
> 팁·필터·빈 플레이트는 `Labware and Consumables`에, 시약은 `Reagent`에 적습니다.
> 플레이트 호텔·인큐베이터 같은 **장치 자체는 `Equipment`**입니다. (전체 규칙은
> 보관함 루트의 `AGENTS.md` → "유닛 오퍼레이션 기록 규칙")

`Experimenter`는 같은 폴더 README의 `author`에서 가져옵니다 — 비어 있으면 빈 값입니다.
`Start_date`는 삽입 시각이 자동으로, `End_date`는 비어 있으니 **작업이 끝나면 값을
클릭해** 채우세요.

### 날짜 · 표

- **`Insert date` / `Insert date and time`**: 커서 위치에 오늘 날짜/시각.
- **`Export tables to CSV`**: 노트 안의 모든 마크다운 표를 각각 CSV로 내보냅니다.
  노트와 **같은 폴더**에 `노트이름.labnote_table1.csv` 식으로 저장됩니다. 워크플로 노트의
  이름이나 번호가 바뀌면 CSV 이름도 따라 바뀝니다.
  파일은 엑셀에서 한글이 깨지지 않도록 UTF-8 BOM으로 저장됩니다. pandas·readr은 그대로
  읽고, Python `csv` 모듈은 `encoding='utf-8-sig'`, R `read.csv`는
  `fileEncoding='UTF-8-BOM'`으로 여세요.

## 샘플 다루기

DNA, 프라이머, 시약 같은 것들을 ID로 추적합니다. **본문에는 참조만 남고, 정의(별칭·설명)는
`{타입}.json`에 저장**되는 구조라, 별칭을 한 번 고치면 모든 노트에서 같은 뜻이 유지됩니다.

### 본문에서 쓰기

편집 중 `@` 뒤에 타입을 치면 자동완성이 뜹니다.

| 입력 | 뜻 |
| --- | --- |
| `@dna`, `@rna`, `@plasmid`, `@primer`, `@protein`, `@reagent`, `@equip`, `@labware` | 그 타입만 검색 |
| `@sample` | 전체 타입 검색 |
| `@item` | `@labware`와 같음 |

목록 아래에 있는 항목이 실제로 만드는 동작입니다:

- **`새 {타입} ID 생성`** — ID를 자동으로 만들어 등록하고 본문에는 참조를 넣습니다.
- **`직접 입력`** — ID·별칭·설명을 손으로 씁니다.
- **`{타입} 카탈로그 검색`** — `Reagent` / `Labware` / `Equip`에서만 맨 위에 나옵니다.
  카탈로그(제품 목록, `resources/labsamples/{타입}_*.json`)에서 골라 참조를 넣습니다.
  카탈로그 파일이 없으면 안내가 뜬 뒤 ID를 자동으로 만들어 등록합니다. 카탈로그에 없는
  시약·소모품·장비는 위의 `새 {타입} ID 생성`·`직접 입력`으로 등록하면 됩니다.

ID는 `{타입}-숫자` 형식만 받습니다(예: `Reagent-1001`). 연구실 관리번호처럼 영문자가
섞인 번호는 ID 대신 **별칭**에 적으세요.

설정에서 추가한 **사용자 정의 타입**도 같은 방식으로 씁니다. 한글 타입(`배지`)이면 `@배지`로
자동완성됩니다. 타입 이름에는 글자·숫자·`_`만 쓰세요(공백이나 `-`가 들어가면 자동완성되지
않습니다).

보관함 최상위 노트(예: `Welcome.md`)에서 샘플을 만들면, 직전에 연 실험과 상관없이 **Global
샘플**로 저장되고 그렇게 알려 줍니다(전역 샘플 폴더가 기본값 `resources/labsamples`일 때).

문법이 궁금하다면: 정의는 `@dna;DNA-1737000000000;별칭;설명`, 참조는 `DNA-1737000000000;별칭`
입니다. 별칭 없이 설명만 쓸 때는 `@dna;ID;;설명`처럼 자리를 비워 두세요.

참조 뒤의 별칭은 **보기용**입니다. 참조는 "이 노트에서 썼다"는 기록만 남기고, JSON에 있는
별칭·설명은 바꾸지 않습니다(참조 뒤에 이어 쓴 문장이 별칭으로 들어가지 않도록). 별칭·설명을
바꾸려면 샘플 뷰에서 `샘플 편집`을 쓰거나 `@` 정의를 쓰세요.

본문에 `ID;별칭` 참조만 적는다고 새 샘플이 등록되지는 않습니다(없는 ID를 참조해도 대장에
생기지 않음). 새 샘플은 위 자동완성 메뉴(`새 {타입} ID 생성`·`직접 입력`·카탈로그 검색),
`@타입;ID;별칭;설명` 정의, 또는 샘플 뷰의 `샘플 추가`로만 만듭니다.

**저장하면 약 1초 뒤 JSON에 반영됩니다.** 단 `.labnote.md` 파일만 대상이라, 일반
`.md` 노트에 쓴 정의는 동기화되지 않습니다.

### 샘플 뷰

리본의 시험관 아이콘 또는 `Open sample view`. 4단 트리입니다:

**Local / Global** → **타입** → **샘플 ID | 별칭** → **별칭·설명**

`Local`은 지금 열어 둔 노트가 속한 실험의 샘플, `Global`은 보관함 전체 공용입니다. 보관함
최상위 노트를 열면 Local이 Global과 같아집니다. 이미지·PDF처럼 노트가 아닌 파일을 열었을 때만
마지막으로 연 실험을 계속 보여 줍니다.
샘플을 우클릭하면 ID 복사, 참조 삽입, 편집, 삭제, **Local ↔ Global 이동**을 할 수 있습니다.

- **참조 삽입**은 커서 위치에 맞춰 들어갑니다. 커서가 머리말(frontmatter)이나 맨 위 제목 위에
  있으면 문서 끝(마지막 절)에, 제목 줄 위에 있으면 그 제목 바로 다음 줄에, `@타입;ID;…` 정의가
  있는 줄(줄 가운데 정의 포함) 위에 있으면 그 줄 다음 줄에, 다른 참조 위에 있으면 그 줄 끝에,
  그 밖에는 커서 자리에 넣습니다. 정의 줄 끝에 붙이면 정의의 설명으로 읽히기 때문입니다.
- **삭제는 본문에서 쓰는 중이면 막힙니다.** 어느 노트에서 쓰는지 보관함 기준 전체 경로로 알려 주니, 본문에서 먼저 지운 뒤
  다시 삭제하세요(Local은 그 실험 폴더, Global은 보관함 전체를 확인).
- 여러 실험에서 함께 쓰는 샘플은 **Local ↔ Global 이동**으로 Global에 두세요. Local 참조를 다른
  실험으로 복사하면 그 실험에서는 정의를 찾지 못합니다.

## AI 도우미

Obsidian 안에서 쓰는 보조 기능입니다 (커밋·이슈·Wiki를 다루는 외부 AI 에이전트와는
별개입니다).

| 명령 | 읽는 것 | 쓰는 곳 |
| --- | --- | --- |
| `AI: Draft Method section` | 지금 노트(유닛 오퍼레이션 안이면 그 블록) | 유닛 오퍼레이션 안이면 **그 `#### Method` 절**을 초안으로 채움(이미 쓴 내용이 있으면 먼저 물어봄). 밖이면 **커서가 있는 줄 다음**에 삽입 |
| `AI: Summarize results` | 지금 노트 전체(선택 영역이 아님) | **커서가 있는 줄 다음**에 요약 불릿 삽입. 커서가 머리말(frontmatter) 안이나 첫 제목 위에 있으면 **문서 끝**(보통 `Conclusions and Discussion` 절)에 붙임 |
| `AI: Extract sample definitions` | 지금 노트 | **본문에는 넣지 않고** 샘플 JSON에만 등록 — 결과는 샘플 뷰에서 확인하고, 본문에 쓸 참조는 직접 넣어야 합니다. 알 수 없는 타입은 건너뛰고, `{타입}-숫자` 형식이 아닌 ID는 새로 만듭니다 |
| `AI: Ask assistant (uses tools)` | 입력한 목표 + 지금 노트 | 보관함을 직접 수정. **쓰기 전에 대상 경로를 보여주고 확인을 받습니다.** 절 내용을 바꿀 때는 지워질 줄 수도 함께 보여 줍니다 |

**설정 위치**: 설정 → 커뮤니티 플러그인 → **Labnote Assistant** → `AI provider` →
**Provider**. 기본값은 `Disabled`라 그대로 두면 AI 명령이 동작하지 않습니다.
`Ollama`(로컬) 또는 `OpenAI-compatible`을 고르고 엔드포인트·모델명을 채우세요.
API 키는 OpenAI 계열에만 전송되며 Ollama로는 절대 나가지 않습니다.

## 자주 겪는 문제

**push했는데 이슈가 안 생겨요**
- 먼저 보관함이 GitHub 저장소와 연결된 git 저장소인지 확인하세요(관리자 설정 완료 여부). 보관함 폴더에 `.git`이 없으면 push 자체가 되지 않습니다. 이때 플러그인은 논의 표시나 이슈 마커를 넣을 때 "아직 git 저장소가 아니라 이슈가 생성되지 않습니다"라고 알려 줍니다. `.labnoteo/SETUP.md`의 저장소 연결을 마치세요.
- 노트에 `@issue` 마커, 논의 표시(`discuss: true`), 또는 `status: needs-review` 중 하나가 있는지 확인하세요 — 이 신호가 있어야 이슈가 열립니다. 본문에 "논의 필요"라고 적은 것만으로는 열리지 않습니다.
- GitHub 저장소의 **Actions 탭**에서 `experiment-issues` 워크플로우가 실행됐는지 확인하세요.

**Actions 탭에 실행 기록 자체가 없어요**
- 이 워크플로우들은 **`labnote/` 아래 파일이 바뀐 push에서만** 돕니다. 설정 파일이나 Wiki 초안만 고쳐 push하면 아무것도 실행되지 않습니다.
- 지금 당장 돌리고 싶다면 **Actions 탭 → `experiment-issues` → `Run workflow`** 를 누르세요. 수동 실행은 바뀐 파일이 아니라 **모든 실험 폴더**를 훑으므로, 그동안 처리되지 않고 남아 있던 마커가 한꺼번에 이슈로 열립니다.

**플러그인은 어떻게 업데이트하나요?**
- BRAT가 앱을 켤 때 자동으로 최신 릴리스를 확인·설치합니다(설정 → `Obsidian42 - BRAT`에서 자동 갱신을 끌 수 있음).
- 지금 바로 받으려면 명령 팔레트 → `Check for updates to all beta plugins and UPDATE`.
- 업데이트 뒤 서버 자동화 동작까지 최신으로 맞추려면 아래 항목을 보세요.

**플러그인을 업데이트했는데 서버 동작이 예전 그대로예요**
- GitHub Actions는 **저장소에 커밋된** `.labnoteo/scripts/*.mjs`를 실행합니다. 플러그인만 업데이트해서는 바뀌지 않습니다.
- 명령 팔레트 → `Setup research automation`을 다시 실행해 스크립트를 갱신하고, `.labnoteo/`를 **커밋하고 push**하세요.

**마커를 넣었는데 이슈가 안 생겨요**
- 마커가 색으로 강조되어 있나요? 강조되지 않으면 형식이 잘못된 것입니다. 형식은 `@issue;<ID>;<주제문장>`이고, 세 부분이 모두 있어야 합니다.
- 손으로 `@issue;논의 필요`처럼 ID 없이 쓰면 무시됩니다. 명령 팔레트 → `Insert issue marker`로 넣으면 ID가 자동으로 붙습니다.
- **Actions 탭**의 `validate`가 실패했다면 어느 줄이 잘못됐는지 알려줍니다.
- 이미 닫은 마커 이슈는 다시 열리지 않습니다. 새 논의는 새 마커로 시작하세요.

**"duplicate marker ID" 경고가 떠요**
- 마커가 있는 줄을 복사해 같은 실험 폴더의 다른 노트에 붙여넣은 것입니다. ID가 겹치면 두 질문이 **한 이슈로 합쳐집니다.**
- 복사된 쪽의 마커를 지우고 `Insert issue marker`로 새로 넣으세요.

**`Insert unit operation`이 "워크플로 파일에서 실행해주세요"라고만 해요**
- README나 일반 노트에서는 동작하지 않습니다. `###_이름.labnote.md` 형식의 워크플로 노트를 열고 실행하세요.
- 워크플로 파일인데도 거부된다면 파일명이 `###_`로 시작하는지, `.labnote.md`로 끝나는지 확인하세요.

**워크플로를 다른 실험으로 옮겼는데 체크리스트에 안 보여요**
- 폴더 간 이동은 자동 등록되지 않습니다. 대상 실험의 README나 실험 폴더를 **우클릭 → `Sync workflow checklist with folder`** 로 등록하세요(명령 팔레트에도 있음).
- 원래 실험에서도 같은 명령을 실행하면 옮겨 간 항목을 확인 후 지웁니다.
- `Insert workflow`를 쓰면 옮긴 파일이 등록되지 않고 카탈로그에서 고른 빈 워크플로 노트가 새로 생깁니다.

**커밋이 거부돼요 (대용량 파일)**
- 50MB 초과 파일은 커밋이 차단됩니다. 파일을 `raw-data/` 등 Git 밖 보관 위치로 옮기고, 노트에는 경로/ID만 남기세요.
- `git commit --no-verify`로 우회하지 마세요 — 서버 검증에서 다시 걸립니다.

**AI 명령이 응답이 없어요**
- 설정 → Labnote Assistant → **Provider**가 `Disabled`가 아닌지(Ollama/OpenAI) 확인하고, 엔드포인트·모델명을 설정하세요.

**노트 검증이 실패해요 (Actions의 validate)**
- `status` 값이 허용 목록(`planned`, `in-progress`, `needs-review`, `completed`, `failed`, `discontinued`, `needs-repeat`)에 있는지, 실험 `id`와 마커 ID가 중복되지 않는지 확인하세요.

**Wiki가 갱신되지 않아요**
- Wiki 발행은 **`main` 브랜치에 들어갔을 때만** 일어납니다. 작업 브랜치에 `wiki-staging/`을 고쳐 push해도 발행되지 않습니다(이슈·검증과 다른 점입니다).
