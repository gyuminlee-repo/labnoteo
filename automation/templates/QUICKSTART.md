> 실험하는 연구원을 위한 문서입니다. 저장소 최초 설정(관리자용)은 `.labnoteo/SETUP.md`를 보세요.
>
> Git·GitHub 자동화를 쓰지 않는다면 [명령 찾는 법](#명령%20찾는%20법)·[기록하기](#기록하기)·[샘플 다루기](#샘플%20다루기)만
> 보면 됩니다. 이 문서는 명령 팔레트 → `Open user guide`(사용법 열기)로 언제든 다시 열 수 있습니다.
>
> `BEGIN labnoteo (managed)`와 `END labnoteo (managed)` 표시 사이는 플러그인이 관리합니다. 이 안을 고치지
> 않았다면 플러그인을 업데이트할 때 새 설명서로 바뀝니다. 고쳤다면 그대로 두고, `Open user guide`로 열 때
> 새 버전으로 바꿀지 묻습니다(바꾸면 옛 파일은 `QUICKSTART.backup.md`로 남음). 연구실 규칙은 맨 아래 표시
> 밖에 적으면 그대로 남습니다.

## 이 보관함으로 하는 일

- Obsidian에서 쓰는 **노트가 곧 공식 연구 기록**입니다 (`labnote/` 폴더).
- 노트를 **push하면 자동으로**: 노트 형식이 검증되고, 논의가 필요한 실험은 GitHub Issue가 열립니다.
- 실험에서 확인된 사실은 **Wiki(논문형 초안)** 에 차곡차곡 쌓입니다.
- 커밋·푸시 같은 Git 작업은 **AI 에이전트에게 말로 시키면** 됩니다.

## 시작 전 확인 (1분)

- 관리자가 `.labnoteo/SETUP.md`의 최초 설정(GitHub 저장소 연결, 훅 활성화)을 마쳤는지
  확인하세요. (`.labnoteo/`는 숨김 폴더라 Obsidian 탐색기에는 보이지 않습니다 —
  탐색기 대신 파일 관리자나 에디터로 열어야 합니다.)
- 명령은 Obsidian **명령 팔레트**(Ctrl/Cmd+P)에서 찾습니다. 한국어 UI에서는
  `실험 생성 (Create experiment)`처럼 한글과 영문이 함께 보여, `실험 생성`으로도
  `Create experiment`로도 검색됩니다([대응표](#명령%20찾는%20법)). `Labnote`로 검색하면
  이 플러그인의 명령만 모입니다. 언어를 바꿨다면 Obsidian을 다시 시작해야 명령 이름이 바뀝니다.

## 5분 따라하기

### 1. 실험 만들기

명령 팔레트 → **`Create experiment`** (실험 생성) → 실험 이름 입력.
`labnote/###_이름/README.labnote.md`가 생기고 바로 열립니다.
폴더 이름에서 공백은 `_`로, 하이픈·대시·물결(`–`, `~`)은 `-`로 바뀌고 그 밖의 기호는
빠집니다(예: `배지 최적화 (M1–M8)` → `001_배지_최적화_M1-M8`). 숫자 앞의 마이너스 부호는
남깁니다(예: `−80°C 보관` → `001_-80C_보관`). 숫자 사이의 소수점도 남고
(예: `OD600 0.4~0.8 수확` → `001_OD600_0.4-0.8_수확`), 숫자 사이의 다른 기호는 숫자가 서로
붙지 않게 바뀝니다. 곱셈기호 `×`는 `x`, 천 단위 쉼표는 빠지고(`2,500` → `2500`), 그 밖의
`/`·`:`·`±`·`,` 등은 `_`가 됩니다(예: `pH 7.0/8.0 비교` → `001_pH_7.0_8.0_비교`,
`3×2 요인 설계, 37±2` → `001_3x2_요인_설계_37_2`). 숫자 사이가 아닌 기호는 빠집니다
(예: `A/B 테스트` → `001_AB_테스트`). 제목 글자가 모두 기호나 이모지면 폴더 이름을 만들 수
없어 실험이 만들어지지 않습니다. frontmatter의 `title`에는 입력한 제목이 그대로 남습니다.
제목이 길면 폴더 이름의 제목 부분은 60자에서 잘립니다. 입력 창 아래에 폴더 이름 기준 글자 수
(`n/60`)가 칠 때마다 나오고, 넘으면 경고 색으로 바뀝니다(만들기는 막지 않음). 이미 만든 폴더는
바꾸지 않습니다. Windows는 보관함 폴더까지 합친 경로가 260자를 넘으면 파일을 열지 못하므로,
그렇게 되면 만들 때 경고합니다. 보관함은 `C:\Users\이름\Documents\labnote`처럼 짧은 경로에 두세요.

**열리자마자 frontmatter의 `author`를 채우세요.** 비워 두면 이 실험에서 이후 만드는
모든 워크플로·유닛 오퍼레이션의 `Experimenter`가 **경고 없이 빈 값**으로 들어갑니다.

README에는 목적(`Experiment Objective`)·관련 워크플로·요약을 기록합니다.

### 2. 진행 상태 바꾸기

명령 팔레트 → **`Change experiment status`** (실험 상태 변경) → 상태 선택
(`planned` → `in-progress` → `completed` / `failed` 등).
목록에는 상태마다 한국어 뜻(`진행 중 — 지금 하고 있음`)이 함께 나오고, `재실험`·`검토`처럼
한국어로 쳐서 찾을 수도 있습니다. 저장되는 값은 영어 그대로입니다.
`needs-review`로 바꾸면 다음 push 때 검토 이슈가 열립니다. 자동화 설정 전이거나 보관함이
아직 git 저장소가 아니면 이슈가 열리지 않는다는 것을 함께 알려 줍니다.
알림은 `planned → in-progress`처럼 바뀌기 전 값도 보여 줍니다. 상태는 어느 실험 노트에서 실행해도
그 실험의 **README**에 들어가므로, 워크플로 노트에서 실행하면 Ctrl+Z가 닿지 않습니다. 이때 알림이
"이 노트가 아니라 …의 README를 바꿨습니다"와 함께 되돌리는 법(같은 명령으로 이전 값 고르기)을 알려 줍니다.

실험 전체의 진행 상태는 **워크플로 뷰**(리본의 상자 아이콘 또는 `Open workflow view`) 맨 위 `실험` 칸에서
한눈에 봅니다. 실험이 상태별로 묶여 `001_GFP · 제목`으로 보이고, 클릭하면 그 실험의 README가 열립니다.
뷰 위의 `실험 검색` 칸에 낱말을 치면 폴더 이름·제목·과제(`project`)·상태로 거르고, 옆의 전환으로
`상태별`·`과제별`·`논의 표시별` 묶음을 오갑니다. README의 `project`를 같은 값으로 채운 실험들이 `과제별`에서 한 묶음으로
모이고(상태가 달라도), 과제가 없으면 `(과제 없음)`에 들어갑니다. `논의 표시별`은 논의 표시가 켜진 실험을
`논의 표시됨`에, 나머지를 `논의 표시 없음`에 모읍니다. 검색 칸에 `논의`나 `discuss`를 쳐도 논의 표시된 실험만 남습니다.
고른 묶음은 다음에도 그대로입니다.
마우스 없이도 됩니다: `Open workflow view`로 열면 포커스가 목록에 들어가고, ↑↓로 이동, →←로 펼치기·접기,
Enter로 열기, Shift+F10이나 메뉴 키로 우클릭 메뉴를 엽니다(샘플 뷰도 같음).
우클릭 → `Change experiment status`로 지금 열린 노트와 상관없이 **그 실험**의 상태를 바꿉니다.
논의 표시(아래 3절)가 켜진 실험은 말풍선 아이콘으로 보이고, 마우스를 올리면 "논의 표시됨"이 나옵니다.
우클릭 → `Toggle discussion flag`로 그 실험의 논의 표시를 켜고 끕니다.

### 3. 기록하다 논의가 필요하면 그 자리에 표시하기

질문이 떠오른 문장을 선택하고 명령 팔레트 → **`Insert issue marker`**
(논의 이슈 마커 삽입). 이런 줄이 만들어집니다:

```markdown
3차 시도에서만 수율 40%. @issue;ISS-mkd8x3k;시드 배양 시간 차이 때문인지 논의 필요
```

`@issue;`부터 줄 끝까지가 한 마커이고, 뒤의 문장이 이슈 제목이 됩니다.
한 노트에 **여러 개**를 달 수 있고 각각 별도 이슈로 열립니다.
실험 폴더 안의 `README.labnote.md`든 워크플로 노트든 **어느 노트에 적어도 됩니다** —
실제로 질문은 대개 작업을 적는 워크플로 노트에서 나옵니다
([폴더 구조](#실험%20폴더의%20구조) 참고).
선택한 문장이 없으면 **이슈 주제 문장**을 묻는 창이 뜹니다. 커서가 있는 줄의 문장(목록 기호·
체크박스·`>`·`#`은 뺀 것)이 미리 채워져 있습니다. 그대로 확인하면 그 문장을 선택했을 때와 같게
들어가고, 다른 문장을 적으면 원문은 그대로 두고 그 문장을 주제로 한 마커를 붙입니다.
비워 두면 확인되지 않고, 취소하면 아무것도 넣지 않습니다(주제가 빈 마커는 검증에서 오류가 됩니다).
목록이나 문장을 **여러 줄** 선택하면 원문은 그대로 두고 마지막 줄 끝에 마커를 붙이며, 주제는 그 줄들을
목록 기호 없이 이은 문장이 됩니다.

문장의 **일부만** 선택하거나, 창에 새 주제를 적었는데 커서가 줄 중간에 있으면, 원문은 그대로 두고 마커를
**줄 끝에** 붙입니다(선택한 부분이 주제). 예: `BS-3 형광 높음 누출 의심`에서
`BS-3 형광`을 선택 → `BS-3 형광 높음 누출 의심 @issue;ISS-…;BS-3 형광`.
문장의 **뒷부분**이나 단어 중간부터 줄 끝까지 선택해도 마찬가지입니다(`누출 의심`만 선택 →
`BS-3 형광 높음 누출 의심 @issue;ISS-…;누출 의심`). 선택한 글을 마커로 바꿔 넣는 것은 줄의 글
(목록 기호·체크박스·`>`·`#` 뒤) **처음부터 끝까지** 선택했을 때뿐입니다.
README의 **워크플로 체크리스트 줄**에서는 링크를 마커로 바꾸지 않고 항상 링크 뒤(줄 끝)에 붙입니다.
주제 창에는 링크 대신 라벨 글자가 미리 채워집니다. 링크가 마커로 바뀌면 그 줄은 더 이상 워크플로 항목이
아니게 되기 때문입니다.
제목 줄에서 실행하면 제목 바로 아랫줄에 넣고, 표 안에서는 넣지 않습니다(표 아래 줄에서 실행).
머리말(frontmatter, 맨 위 `---` 사이) 안에서도 넣지 않습니다(본문에서 실행).
코드 블록(```` ``` ````나 `~~~`로 감싼 부분, 또는 빈 줄 다음에 4칸·탭으로 들여쓴 부분) 안도 넣지 않습니다.
자동화가 코드 블록을 건너뛰어 이슈가 열리지 않기 때문입니다. 마커 문법을 예로 적어 둔 코드 블록 안의
마커는 강조되지 않고 검증에도 걸리지 않습니다. 주석(`<!-- -->`, `%% %%`) 안도 같습니다. 주석은 읽기
화면에 보이지 않으므로, 끝난 논의의 마커를 주석으로 감싸 두면 강조되지 않고 자동화도 건너뜁니다(이미 열린
이슈는 닫히지 않고 그대로 남습니다). 들여쓴 코드 블록과 주석을 이렇게 건너뛰는 동작은 플러그인
업데이트 후 `Setup research automation`(연구노트 자동화 설정)을 다시 실행해야 서버 자동화에도 반영됩니다.
이슈는 **`Setup research automation`(연구노트 자동화 설정)을 실행한 보관함**에서만
열립니다. 설정 전이면 명령이 그렇게 알려 줍니다.

`ISS-...`는 자동으로 붙는 식별자입니다. 이게 있어야 나중에 주제문장을 고쳐도
같은 이슈로 유지됩니다. **직접 짓지 마세요** — 명령이 만들어 줍니다.
마커가 색으로 강조되지 않는다면 형식이 잘못된 것이라 이슈가 열리지 않습니다.
같은 이유로 **마커가 있는 줄을 복사해 다른 노트에 붙여넣지 마세요** — ID가 따라가
두 질문이 한 이슈로 합쳐집니다. 복사했다면 그 줄의 마커를 지우고 새로 삽입하세요.
같은 실험 안에서 ID가 겹치면 편집 화면에서 두 마커에 물결 밑줄이 생기고(마우스를 올리면 어느 노트와
겹치는지 보임), 저장하면 한 번 알려 줍니다.

**실험 전체를 놓고 논의해야 한다면** 지점 마커 대신 명령 팔레트 →
**`Toggle discussion flag`**(논의 표시 전환)을 씁니다. 진행 상태(`status`)와는
별개라 `in-progress`인 채로 논의만 올릴 수 있습니다. 워크플로 노트에서 실행해도 표시는
그 실험의 **README**에 붙고, 알림이 "이 노트가 아니라 …의 README를 바꿨습니다"라고 알려 줍니다.
워크플로 뷰의 실험 **우클릭** → `Toggle discussion flag`로도 켜고 끌 수 있고, 표시된 실험은 말풍선
아이콘으로 보입니다.

> 본문에 "논의 필요"라고 **쓰기만 해서는 이슈가 생기지 않습니다.** 마커나
> 논의 표시가 있어야 열립니다. 본문을 읽고 판단하게 하려면 AI 에이전트에게:
> *"이 실험 노트 읽고 논의가 필요해 보이면 표시해줘"*
> — 에이전트가 맥락을 판단해 (확인 후) 같은 표시를 남깁니다.

### 4. 커밋·푸시하기

AI 에이전트(Claude Code 등)에게 말하면 끝입니다:

> "오늘 작업 커밋하고 푸시해줘"

AI 에이전트(opencode / Claude Code / Codex)가 **Copilot에 연결되어 있어야** 합니다 — 에이전트를
고를 수 없거나 말해도 반응이 없으면 관리자에게 문의하세요(연결은 관리자용 설치 가이드 참고).
에이전트가 노트를 고치기 전에 보고 싶으면 입력창 아래 권한을 `Plan`으로 두세요(Claude).
기본 `Safe`는 노트 편집을 확인 없이 바로 적용할 수 있습니다.

에이전트는 이 보관함의 `AGENTS.md` 규칙에 따라 커밋 메시지를 자동 작성하고,
대용량 파일 검사를 통과한 뒤 push합니다. (직접 `git add / commit / push` 해도 됩니다.)

커밋할 때 노트 검증 경고가 뜰 수 있습니다. **커밋을 막지는 않지만**, 그대로 push하면
서버 검증이 같은 내용으로 실패하니 먼저 고치는 편이 낫습니다.

### 5. 이슈 자동 생성 확인하기

push하고 잠시 뒤, GitHub 저장소의 **Issues 탭**을 열어 보세요.

- `@issue` 마커마다 `[실험ID/ISS-...] 주제문장` 이슈가 열립니다. 본문에는 그
  마커가 있던 **노트의 정확한 줄로 가는 링크**가 들어 있어, 어떤 맥락에서 나온
  질문인지 바로 확인할 수 있습니다.
- 논의 표시(`discuss`)나 `status: needs-review`로 표시한 실험은 `[실험ID] 제목`
  이슈 하나가 열립니다. 이 이슈는 실험 전체의 논의 스레드라서, 닫았다가
  나중에 다시 표시하면 같은 이슈가 다시 열립니다.

(실험ID는 frontmatter의 `id`가 있으면 `EXP-###`, 없으면 폴더명 `###_이름`입니다.)

**바뀐 노트만 보는 게 아닙니다.** 자동화는 이번 push에서 바뀐 파일이 속한
**실험 폴더 전체**를 훑습니다. 예전 push 때 적어 두고 잊은 마커가 같은 폴더에
있었다면, 그 폴더의 아무 노트나 다시 고쳐 push하는 것만으로 함께 처리됩니다.

논의가 끝나면 GitHub에서 이슈를 닫으면 됩니다. 노트의 마커를 지워도 이슈는
닫히지 않고, 닫힌 마커 이슈가 다시 열리지도 않습니다.

> **작업 브랜치에 push해도 이슈는 열립니다.** 검증과 이슈 생성에는 브랜치 제한이
> 없습니다. 아직 논의를 올리고 싶지 않다면 마커를 나중에 넣으세요.

## Wiki에 결과 쌓기 (실험이 마무리되면)

1. AI 에이전트에게: *"이 실험에서 확인된 객관적 사실을 wiki-staging에 정리해줘"*
   — 에이전트가 `wiki-staging/`의 논문형 섹션(Methods, Results 등)에
   **사실 + 근거 실험ID**만 추가합니다 (해석·결론은 사람 몫).
2. 초안을 읽고 검토·수정합니다.
3. **`main`에 머지되어야** GitHub Wiki로 발행됩니다. 이슈와 달리 작업 브랜치에
   push하는 것만으로는 발행되지 않습니다.

### 팔레트에 없는 기능 (우클릭 · 클릭 전용)

팔레트만 훑어서는 존재를 알 수 없는 것들입니다.

| 기능 | 어디서 | 하는 일 |
| --- | --- | --- |
| **Insert workflow** (워크플로 삽입) | `README.labnote.md` 편집 중 **우클릭** | 카탈로그에서 고른 워크플로 파일을 **새로** 만들고 이 README의 체크리스트에 등록. 이미 있는 파일(옮겨 오거나 복사한 것)을 등록하는 기능이 아닙니다 — 그때는 `Sync workflow checklist with folder`를 쓰세요. |
| **Go to definition** (정의로 이동) | 샘플 ID나 참조의 별칭 위에서 **우클릭** | 그 샘플의 타입·별칭·설명·저장 파일을 팝업으로. 설정에서 **샘플 추적이 꺼져 있으면 메뉴 자체가 뜨지 않습니다.** 일반 `.md` 노트에서도 됩니다. 키보드로는 팔레트의 `Open sample definition`이 같은 창을 엽니다. |
| **날짜 선택기** | `#### Meta`의 `Start_date` / `End_date` 줄 끝 **📅 아이콘** 또는 **값을 클릭** | 달력·시계 피커. 📅 아이콘은 값이 있어도 항상 보입니다. 바꾼 값은 바로 노트에 들어가고, Enter나 바깥 클릭으로 닫힙니다. Esc를 누르면 연 시점의 값으로 되돌리고 닫습니다. 값이 이미 있으면 아무것도 고르지 않고 Enter로 닫아도 그대로 둡니다(`2026.10.23 14:00`처럼 점으로 적은 날짜도 읽어서 보여 주며, 읽지 못하는 값도 바꾸지 않음). 빈 값이면 지금 시각을 보여 주고 Enter로 그 시각을 넣습니다. 연도 칸을 ↑↓로 넘기거나 직접 치다가 1900~2100년을 벗어난 값은 노트에 쓰지 않고, 닫을 때 "1900~2100년만 기록합니다"라고 알립니다. 선택기로 여러 번 바꿔도 **Ctrl+Z 한 번**으로 연 시점의 값으로 돌아갑니다. 같은 블록에 `Start_date`가 있으면 `End_date` 달력은 그보다 이른 날을 고를 수 없게 하고, 그래도 시작보다 이른 종료 시각이 되면 닫을 때 "End_date(…)가 Start_date(…)보다 이릅니다"라고 알려 줍니다(값은 그대로 기록). 새 창으로 띄운 노트에서는 그 창에 열립니다. 읽기 모드에서는 동작하지 않습니다. |
| **표 CSV 내보내기** | 파일 탐색기에서 노트 **우클릭** | 팔레트 명령과 동일. |
| **노트 QR 아이콘** | 실험 노트(`*.labnote.md`) 위쪽 오른편 | 노트 ID와 QR을 보여 주고, 워크플로 노트면 `실험 기록지 출력` 버튼도 있습니다. 팔레트의 `Show note barcode`와 같습니다. |
| **리본 아이콘 3개** | 왼쪽 사이드바 | 상자 = 워크플로 뷰(맨 위에 실험 목록, 상태별), 시험관 = 샘플 뷰, 스캔 = `Import scanned pages`. 실험은 `001 · 제목 (2/5)`처럼 번호·제목과 README 체크리스트의 완료/전체 워크플로 수로 보이고, 마우스를 올리면 폴더·상태·과제·마지막 수정일이 나옵니다. 위의 `실험 검색`·`상태별/과제별/논의 표시별` 전환으로 거르고 묶습니다. 허용되지 않는 `status`(예: `Failed`) 묶음에는 `(허용되지 않는 상태)`가 붙습니다. |
| **실험 목록에서 상태 변경** | 워크플로 뷰의 실험 **우클릭** | 그 실험의 README `status`를 바로 바꾸거나 논의 표시를 전환. 상태 창 제목과 알림에 실험 폴더 이름이 나오고, 되돌리려면 같은 실험을 다시 우클릭합니다. 논의 표시된 실험은 말풍선 아이콘. 클릭하면 README를 엶. |

## 실험 폴더의 구조

`Create experiment`가 만드는 것과, 쓰다 보면 생기는 것:

```
labnote/
  001_Yield_optimization/
    README.labnote.md          ← 실험의 얼굴. 목적·워크플로 목록·요약
    001_WD010_General_Design_of_Experiment.labnote.md   ← 워크플로 노트
    002_WB020_Cloning.labnote.md
    images/                    ← 그림 넣는 곳
      scans/                   ← 출력본 사진·스캔 (플러그인이 저장)
    resources/
      labsamples/              ← 이 실험에서만 쓰는 샘플 (DNA.json, Primer.json …)
resources/
  labsamples/                  ← 보관함 전체에서 공유하는 샘플
  workflows/                   ← 워크플로·유닛 오퍼레이션 카탈로그 (수정 가능)
```

**그림 붙여넣기**: Obsidian은 기본으로 붙여넣은 그림을 보관함 맨 위에 저장합니다. `Setup research automation`을
마치면 `./images`(노트 옆 `images/`)로 바꿀지 묻고, 바꾸면 실험 노트의 그림은 그 실험의 `images/`에 들어갑니다.
나중에 바꾸려면 설정 → 파일 및 링크 → 새 첨부 파일의 기본 위치를 "현재 폴더 아래 지정된 폴더", 폴더 이름을
`images`로 두세요. 실험 밖 노트에서 붙여넣으면 그 노트 옆 `images/`에 저장됩니다.

**실험 폴더는 `labnote/` 바로 아래에 둡니다.** `labnote/묶음/020_GFP`처럼 하위 폴더에 넣으면 실험으로
인식되지 않아 경고하고 `labnote/` 아래로 되돌릴지 묻습니다.

**`@issue` 마커는 이 폴더 안 어느 `.labnote.md`에 적어도 됩니다.** 자동화는 폴더
전체를 훑기 때문입니다.

README frontmatter:

| 필드 | 뜻 | 기본값 |
| --- | --- | --- |
| `title` | 실험 제목 | 입력한 이름 |
| `author` | 실험자 | **빈 값 — 직접 채우세요** |
| `experiment_type` | `labnote`여야 검증·자동화 대상이 됩니다 | `labnote` |
| `sample_tracking` | 이 실험에서 샘플 자동완성·하이라이트·대장 기록을 쓸지(`no`면 끔) | `yes` |
| `status` | 진행 상태 (`Change experiment status`로 변경). `completed`를 고를 때 체크하지 않은 워크플로나 `end_date`가 빈 워크플로 노트가 있으면 개수를 보여 주고 확인을 받습니다 | `planned` |
| `project` | 상위 과제명. 워크플로 뷰에서 `과제별`로 묶을 때와 실험 검색에 쓰이고, 실험 툴팁에 나옵니다 | 빈 값 |
| `created_date` | 만든 날 | 오늘 |
| `last_updated_date` | 마지막 기록일. 노트를 고치면 하루 한 번 자동으로 오늘이 됩니다(워크플로 노트를 고치거나 새 워크플로를 만들면 README도). 설정 → Labnote Assistant → 워크플로 → `마지막 갱신일 자동 기록`으로 끌 수 있습니다. 날짜를 손으로 고친 노트는 그날만 그 날짜를 그대로 둡니다 | 오늘 |
| `id` | `EXP-###` 식별자 (선택). 없으면 폴더명이 실험ID | 없음 |
| `discuss` | 논의 표시 (`Toggle discussion flag`가 켜고 끕니다). 손으로 적을 때는 `true` 외에 `yes`·`예`도 켬으로 읽고, 그 밖의 값(예: `maybe`)은 꺼짐으로 읽으며 서버 `validate`가 경고합니다 | 없음 |

## 기록하기

### 워크플로 노트 (실험의 단계)

명령 팔레트 → **`Create workflow`** → 카탈로그에서 단계 선택 → 별칭 입력.
`002_WB020_Cloning_형질전환.labnote.md`처럼 **번호 + 카탈로그 코드 + 이름** 형식으로
만들어지고, README의 `## 🗂️ Related Workflows` 체크리스트에 자동 등록됩니다.
새 줄은 번호가 같거나 작은 마지막 항목 바로 뒤에 들어가고, 이미 있는 줄과 그 사이에 적은 할 일·메모는
건드리지 않습니다. 절 제목은 `## 관련 워크플로`처럼 우리말로 바꿔도 알아봅니다. 제목을 아예 다른 말로
바꾸면 워크플로 항목이 있는 첫 `##` 절을 쓰고, 그런 절도 없으면 등록하지 못했다고 알려 줍니다.
별칭에 `[재]`, `LOC-01]`처럼 대괄호를 써도 됩니다. 체크리스트 링크에는 `\[재\]`처럼 적혀
읽기 화면에서는 입력한 그대로 보입니다.
한국어 UI에서는 카탈로그를 `조립`·`클로닝`처럼 한국어로도 검색할 수 있고, 목록의 설명도 한국어로 나옵니다
(`Insert unit operation`과 워크플로 뷰 툴팁도 같음, 영어 설명의 낱말로도 검색됨). 연구실이 `resources/workflows/`의
카탈로그 설명을 고쳤거나 직접 추가한 항목은 고친 영어 설명이 그대로 나옵니다.
플러그인 업데이트로 내장 카탈로그가 바뀌면 앱을 열 때 한 번 알림이 뜹니다. 명령 팔레트 →
`Update catalogs`를 실행하면 새 항목이 추가되고, 연구실이 손대지 않은 이름·설명이 새 값으로 바뀝니다
(바뀔 목록을 확인한 뒤 반영, 고친 값과 지운 항목은 그대로). 팀에서는 한 사람이 실행해 커밋하면 됩니다.
카탈로그 이름이 바뀌어도 **이미 만든 워크플로 노트와 README 체크리스트의 이름은 그대로**입니다(확인 창에
그 항목을 쓰는 노트 수가 나옵니다). 새 이름으로 맞추려면 노트의 `title`과 `## [ID 이름]` 제목(유닛 오퍼레이션은
`### [ID 이름]`)을 직접 고치고, 워크플로 노트는 파일 이름의 카탈로그 이름 부분도 고친 뒤
`Sync workflow checklist with folder`로 체크리스트 라벨을 맞추세요.
별칭 입력 창에는 워크플로가 무엇인지와 고른 항목의 설명이 나오고, 칠 때마다 파일 이름 기준 글자 수
(`n/남은 칸`)를 알려 줍니다. 남은 칸은 `ID_카탈로그이름_` 뒤에 남는 자리라 워크플로마다 다르며,
넘으면 경고 색으로 바뀌지만 저장은 막지 않습니다.
같은 실험에 **같은 ID와 같은 별칭**(둘 다 비어 있는 경우 포함)의 워크플로가 이미 있으면, 그 파일 이름과
함께 체크리스트에서 둘이 똑같이 보인다는 경고가 뜹니다. 역시 막지는 않습니다.
파일 이름에서 단어 끝 `+`·`-`는 `_plus`·`_minus`로 바뀝니다(`IND+` → `IND_plus`, `IND-` → `IND_minus`).
`M1-M8`, `-80C`는 그대로입니다. 이전 버전에서 만든 `…_IND.labnote.md`도 같은 노트로 알아봅니다.
별칭이 아주 길면 파일 이름의 번호 뒤 `ID_이름_별칭` 부분은 80자에서 잘립니다(노트의 `title`·별칭과
체크리스트는 그대로). 0.103.0까지 100자로 만든 파일 이름은 바꾸지 않고, 체크리스트도 계속 알아봅니다.

- 탐색기에서 **이름을 바꾸면** README 체크리스트의 그 줄 링크가 새 이름을 따라갑니다. 바뀐 번호가 앞뒤
  항목의 번호 순서에 맞지 않을 때만 **그 줄 하나**를 번호 자리로 옮깁니다(그 아래 더 들여 쓴 하위 할 일은
  함께 옮김). 직접 적은 할 일·메모 줄과 다른 항목의 순서, 링크 뒤에 적은 마커·메모는 그대로입니다.
  탐색기 이름 칸에는 `.labnote`까지 보이니, 덧붙일 말은 `.labnote` **앞**에
  넣으세요(`001_WB030_Gibson v3.labnote.md`).
  체크리스트 라벨이 옛 파일 이름과 같았다면 라벨도 새 이름을 따라갑니다. 노트의 `title`과
  `## [ID 이름]` 제목도 옛 파일 이름과 같았다면 새 이름을 따라갑니다(파일 이름의 `_`는 공백으로
  들어갑니다). 직접 고친 라벨·title은 그대로 둡니다. 그 노트의 표 CSV(`노트이름.labnote_table1.csv`)도
  함께 옮겨집니다.
- 이름을 바꾸다 형식이 깨지면 경고와 함께 고칠 이름을 제안합니다. 제안할 이름이 없거나(예: 번호가
  `01_`처럼 두 자리가 됨) 그 이름의 파일이 이미 있으면 원래 이름으로 되돌릴지 묻습니다. 제안을
  받아들이거나 직접 형식에 맞게 고치면 체크리스트가 다시 그 파일을 따라갑니다
  (Obsidian을 다시 시작하기 전에 고쳐야 합니다).
- 파일 이름의 **카탈로그 ID**(`WD010` 등)만 바꾸면 노트는 그대로 옛 워크플로라서, 체크리스트에 새 ID와
  옛 이름이 섞여 보입니다. 이때 경고와 함께 원래 이름으로 되돌릴지 묻습니다. 다른 워크플로가 필요하면
  `Create workflow`로 새 노트를 만드세요.
- 실험 폴더의 **`README.labnote.md` 이름을 바꾸거나 다른 곳으로 옮기면** 그 실험이 실험 목록과
  워크플로 체크리스트에서 사라지므로, 경고와 함께 원래 이름으로 되돌릴지 묻습니다.

  없습니다" 알림이 뜹니다. 대상 실험에서 `Sync workflow checklist with folder`

  섞이지 않도록). 이 변경은 별칭 창을 취소해도 남습니다.

  번호·제목이 원본과 같아 워크플로 뷰에 똑같이 보인다고 알려 주니, 폴더 이름과 README 제목을 직접 고치세요.

  고칩니다. README의 `author`를 나중에 바꿨다면 노트의 실험자(`experimenter`)도

  `- Experimenter:` 줄 중 옛 이름이거나 비어 있는 줄을 새 이름으로 고칩니다(다른 사람 이름은 그대로).

**워크플로 노트를 연 상태에서** 명령 팔레트 → **`Insert unit operation`** →
카탈로그에서 장비/소프트웨어 작업 선택 → 별칭 입력. 워크플로 노트가 아닌 곳에서 실행하면
목록을 띄우기 전에 무엇이 문제인지 알려 주고 아무 일도 일어나지 않습니다. README에서는 "README는
실험 개요라 유닛 오퍼레이션을 넣지 않는다"며 워크플로 노트를 열거나 `Create workflow`로 만들라고 하고,
`labnote/묶음/020_GFP`처럼 하위 폴더로 옮긴 실험에서는 `labnote/` 아래로 되돌리라고 알려 줍니다.
별칭은 같은 작업을 여러 번 할 때 회차·조건을 구분하는 이름입니다. `[UHW180 Incubation]` 뒤에
`1차 37도`를 적으면 헤딩이 `### [UHW180 Incubation] 1차 37도`, 목차가
`UHW180 Incubation | 1차 37도`가 됩니다. 비워 두고 Enter를 누르면 별칭 없이, Esc를 누르면 넣지 않습니다.
별칭은 파일 이름에 쓰이지 않아 글자 수 제한이 없고, 창에는 글자 수와 유닛 오퍼레이션이 무엇인지,
고른 작업의 설명이 나옵니다.
워크플로 뷰에서 유닛 오퍼레이션을 우클릭해 넣을 때도 같습니다.

`### [UHW010 Liquid Handling]` 헤딩과 `#### Meta`(실험자·시작/종료 시각),
그리고 Input / Method / Output 같은 빈 섹션이 들어갑니다. 카탈로그에 장비가 정해진 HW 작업이면
그 장비 이름이 `#### Equipment` 절에 미리 들어갑니다. 커서가 유닛 오퍼레이션 블록 안이면
**그 블록 다음**, 목차와 첫 블록 사이면 첫 블록 앞, 그 밖(머리말·목차 위·결론 절)이면
마지막 블록 다음에 들어가고, 완료 알림이 위치(`(… 다음)` 등)를 알려 줍니다. 노트가 **읽기 화면**이면
편집 화면으로 바꾼 뒤 마지막 블록 다음에 넣고 그렇다고 알려 줍니다(시료 목록 삽입·샘플 참조 넣기·AI 초안처럼
커서 위치에 넣는 다른 명령도 편집 화면으로 바꾼 뒤 노트 끝에 넣습니다). 삽입 후 문서 맨 위
`## Related Unit Operations` 목차가 헤딩 순서대로 다시 만들어집니다. **유닛 오퍼레이션
블록을 옮기거나 지워도** 목차가 자동으로 다시 정렬됩니다(설정 → Labnote Assistant →
워크플로 → `유닛오퍼레이션 TOC 자동 정렬`, 기본 켜짐). 이 설정을 **꺼도** 목차의 순서만
그대로 둘 뿐, 유닛 오퍼레이션 이름을 바꾸면 목차의 이름과 링크는 계속 맞춰 줍니다.
순서는 Obsidian **Outline** 보기에서 헤딩을 드래그해 바꿀 수 있으며, 목차와 `---` 구분선이 자동으로 정리됩니다. 다른 유닛 오퍼레이션 위에 놓으면 Outline은 그 아래 항목처럼 들여쓴 표시선을 보여 주지만, 블록은 쪼개지지 않고 그 유닛 오퍼레이션 블록 전체의 뒤로 들어갑니다. 정리는 이동과 별도로 저장되므로, 이동 전으로 되돌리려면 Ctrl+Z를 두 번 눌러야 할 수 있습니다.
목차 링크는 GitHub에서 노트를 볼 때 해당 블록으로 이동하는 용도입니다. Obsidian에서는 **Outline**(한국어 UI: 개요) 보기를 클릭해 이동하세요 — 같은 유닛 오퍼레이션이 여러 번 들어가도 각각 구분됩니다.

`Experimenter`는 같은 폴더 README의 `author`에서 가져옵니다 — 비어 있으면 빈 값입니다.
`author`를 나중에 채웠거나 바꿨다면 `Sync workflow checklist with folder`로 이미 만든 노트의

### 날짜 · 표

- **`Insert date` / `Insert date and time`**: 커서 위치에 오늘 날짜/시각.
  머리말(frontmatter) 안에서는 `end_date: ''`처럼 값이 빈 줄만 채우고, 값이 있는 줄에서는
  YAML이 깨지지 않도록 넣지 않고 경고합니다. `#### Meta`의 `- Start_date: ''`·`- End_date: ''`처럼
  빈 줄에서도 따옴표 안을 채우고, 값이 있으면 옆의 📅 피커로 바꾸라고 안내합니다.
  표 칸을 편집하는 중이면 그 칸의 커서 자리에 그대로 넣습니다. 읽기 화면에서도 명령 팔레트에
  보이며, 이때는 편집 화면으로 바꿔 커서를 둔 뒤 다시 실행하라고 안내합니다.
- **`Export tables to CSV`**: 노트 안의 모든 마크다운 표를 각각 CSV로 내보냅니다.
  노트와 **같은 폴더**에 `노트이름.labnote_table1.csv` 식으로 저장됩니다. 워크플로 노트의
  이름이나 번호가 바뀌면 CSV 이름도 따라 바뀝니다.
  읽기 화면에서 표로 보이는 것만 내보냅니다. 문장 바로 아랫줄에 쓴 표는 빈 줄이 없어 읽기 화면에서
  글로 이어 보이므로 내보내지 않고 알림에 그 개수를 알려 줍니다. 표 위에 빈 줄을 넣고 다시 내보내세요
  (그 사이 번호가 밀려 쓰이지 않게 된 CSV는 목록을 보여 주고 휴지통으로 옮길지 묻습니다).
  표가 10개 이상이면 번호를 표 개수의 자릿수에 맞춰 `table01` … `table11`처럼 붙이므로, 파일 탐색기나
  엑셀에서 이름순으로 봐도 표 순서대로 놓입니다. 표가 늘거나 줄어 자릿수가 바뀌면 이미 있던 CSV
  (`table1.csv` → `table01.csv`)는 내보낼 때 새 이름으로 바뀌고 알림이 뜹니다. 분석 스크립트에서 그 파일
  경로를 쓰고 있다면 함께 고치세요.
  칸 수와 서식 기호는 읽기 화면의 표에 맞춥니다. 머리글보다 칸이 많은 행은 넘치는 칸을 버리고, 모자란
  행은 빈 칸으로 채웁니다. 셀 안의 `<br>`은 셀 안 줄바꿈이 됩니다.
  `**굵게**`·`*기울임*`·`` `코드` `` 같은 서식은 기호만 빼고 글자만 남기고, `~~취소선~~`은 글자까지
  뺍니다(`~~0.10~~ 0.12` → `0.12`). `2*3`, `sample_id_1`처럼 단어 안의 기호, `\*` 같은 이스케이프,
  코드 안의 글자는 그대로 둡니다. 링크(`[[노트|별칭]]`, `[글](주소)`)는 적어 둔 그대로 나갑니다.
  코드 블록 안의 표(문법 예시 등)는 읽기 화면에서도 표가 아니므로 내보내지도, 번호를 세지도 않습니다.
  빈 줄 뒤에 4칸 들여 쓴 코드 블록 안의 표도 같습니다(목록 항목 아래 들여 쓴 표는 표로 내보냄).
  주석(`<!-- … -->`, `%% … %%`) 안에 넣어 둔 표도 읽기 화면에 보이지 않으므로 내보내지 않고,
  번호도 세지 않습니다. 알림은 "주석 안에 있어 보이지 않는 표"와 "위에 빈 줄이 없는 표"를
  따로 알려 줍니다.
  콜아웃·인용(`> | … |`) 안의 표는 읽기 화면처럼 표로 내보냅니다. 이 때문에 전에 내보낸 노트의 표 번호가
  밀리면 아래의 덮어쓰기 확인 창이 먼저 물어봅니다.
  같은 표의 값만 고쳤거나, 값은 그대로 두고 머리글만 고쳐 다시 내보내면 묻지 않고 덮어씁니다.
  표를 앞에 추가·삭제해 번호가 밀려서 기존 CSV에 **다른 표**가 들어가게 되면
  `파일 이름: 옛 머리글 → 새 머리글` 목록을 보여 주고 확인을 받은 뒤 덮어씁니다(취소하면 아무것도
  쓰지 않음). 머리글이 같은 표끼리 자리가 바뀌면 `(2행 → 1행)`이나 `(1번째 행: … → …)`처럼
  무엇이 달라지는지 함께 보여 줍니다. 머리글과 값을 함께 고쳤다면 "머리글이 바뀌었습니다" 목록으로 묻습니다.
  다만 표를 지우면서 남은 표의 값까지 함께 고치면 자리가 밀린 것을 알아보지 못하고 묻지 않고
  덮어씁니다. 표를 지운 뒤에는 값을 고치기 전에 한 번 내보내세요.
  내용이 같은 CSV는 다시 쓰지 않고, 완료 알림에 실제로 쓴 개수와 그대로 둔 개수를 따로 알려 줍니다.
  완료 알림에는 저장한 폴더와 파일 이름(앞 3개, 나머지는 "외 N개")도 함께 나옵니다. Obsidian 파일
  탐색기는 기본 설정에서 CSV를 보여 주지 않으므로, **설정 → 파일 및 링크 → 모든 파일 확장명 인식**이
  꺼져 있으면 알림에 그 안내가 붙습니다. 켜지 않아도 파일은 그 폴더에 있습니다(엑셀·탐색기에서 열면 됨).
  표를 지운 뒤 다시 내보내면, 이제 없는 표의 CSV(예: 표가 2개로 줄었을 때의 `…_table3.csv`)를
  보여 주고 확인을 받은 뒤 휴지통으로 옮깁니다. 거절하면 그대로 둡니다.
  파일은 엑셀에서 한글이 깨지지 않도록 UTF-8 BOM으로 저장됩니다. pandas·readr은 그대로
  읽고, Python `csv` 모듈은 `encoding='utf-8-sig'`, R `read.csv`는
  `fileEncoding='UTF-8-BOM'`으로 여세요.
  CSV를 **엑셀에서 더블클릭으로 열면** `3-1`·`1/2`·`SEPT9`가 날짜로, `2:1`·`10:30`이 시각(`2:01`)으로
  바뀌고 `007`의 앞자리 0이 사라집니다. CSV 파일 자체에는 적어 둔 글자가 그대로 들어 있고, 엑셀이 열면서 바꾸는 것입니다.
  엑셀에서는 **데이터 → 텍스트/CSV에서**로 열고 그 열의 형식을 **텍스트**로 지정하세요
  (원본 파일은 65001: 유니코드(UTF-8)). 이런 칸이 있으면 내보내기 알림이 그 보기를 들어 알려 줍니다.
  `=`·`@`로 시작하거나 숫자가 아닌데 `+`·`-`로 시작하는 칸(`=2:1`, `+82-2-000-0000`)은 엑셀이
  수식으로 읽지 않도록 앞에 탭을 붙여 적어 둔 글자 그대로 보이게 합니다. `-80`·`+5` 같은 숫자는
  그대로 둡니다. pandas·R로 읽으면 그 칸 앞에 탭이 남으니 필요하면 `str.strip()`(R은 `trimws()`)으로 지우세요.
  한 글자 `+`·`-`는 보통 그대로 두지만(숫자 열의 `-`는 "없음" 표시), 같은 열에 `+/-`·`++`처럼
  수식으로 읽히는 칸이 있으면(생장 점수 등) 그 열의 한 글자 `+`·`-`에도 탭을 붙입니다. 머리글 행은
  이 판단에 넣지 않습니다.
  서식 처리와 한 글자 규칙 때문에 서식이 든 표나 점수 열이 있는 표는 다음 내보내기 때 CSV 내용이
  새로 바뀌어 덮어써집니다. 머리글과 값이 함께 바뀌는 표라면 "머리글이 바뀌었습니다" 확인이 한 번 뜹니다.

## 샘플 다루기

DNA, 프라이머, 시약 같은 것들을 ID로 추적합니다. **본문에는 참조만 남고, 정의(별칭·설명)는
`{타입}.json`에 저장**되는 구조입니다. 샘플 뷰의 `샘플 편집`으로 별칭을 고치면, 옛 별칭을 쓴
노트(Local 샘플은 그 실험, Global 샘플은 보관함 전체)를 목록으로 보여 주고 함께 고칠지 묻습니다.

### 본문에서 쓰기

편집 중 `@` 뒤에 타입을 치면 자동완성이 뜹니다.

| 입력 | 뜻 |
| --- | --- |
| `@dna`, `@rna`, `@plasmid`, `@primer`, `@protein`, `@reagent`, `@equip`, `@labware` | 그 타입만 검색 |
| `@sample` | 전체 타입 검색 |
| `@item` | `@labware`와 같음 |

이미 있는 샘플은 `로컬 DNA 샘플`(이 실험)과 `전역 DNA 샘플`(보관함 공용)로 구분되어 보입니다.
같은 ID가 양쪽에 있으면 로컬이 먼저입니다. 새 샘플을 만들 때 같은 실험(또는 전역끼리)에 같은
타입·같은 별칭이 이미 있으면, 설명·보관 위치를 묻기 전에 `있는 샘플 {ID} 쓰기`와
`그래도 새로 만들기` 중에서 고르게 합니다. 같은 별칭 샘플이 여럿이면 `있는 샘플 {ID} 쓰기`가 샘플마다
설명·보관 위치와 함께 나옵니다. 그대로 만들면 자동완성에 글자까지 똑같은 줄이 생겨
설명으로만 구분할 수 있으니, 대개는 있는 샘플을 쓰는 편이 좋습니다. 로컬에 만드는데 전역에만 같은
별칭이 있는 경우는 자동완성이 로컬·전역으로 구분해 주므로 알림만 뜹니다.

`@dna;` 뒤에 친 글자로 검색하다가 `;`를 한 번 더 치면(`@dna;DNA-1;별칭`처럼 정의를 직접 쓰는 중)
자동완성이 닫힙니다.

목록 아래에 있는 항목이 실제로 만드는 동작입니다. `;` 뒤에 쳐 둔 글자는 그대로 이어집니다.
`DNA-123`처럼 그 타입의 ID 형식이면 `직접 입력`의 ID 칸에, 아니면 새 샘플의 별칭 칸에 미리 채워집니다.

- **`새 {타입} ID 생성`** — ID를 자동으로 만들어 등록하고 본문에는 참조를 넣습니다.
- **`직접 입력`** — ID·별칭·설명을 손으로 씁니다. 이미 있는 ID를 넣으면 그렇다고 알리고
  지금 값을 채워 보여 줍니다. 새 설명은 기존 설명 앞에 더해지고, 칸을 비우면 기존 값이
  유지됩니다. 값을 지우거나 바꾸려면 샘플 뷰의 `샘플 편집`을 쓰세요.
- **`{타입} 카탈로그 검색`** — **그 타입의 제품 카탈로그 파일이 있을 때만** 맨 위에 나옵니다.
  카탈로그에서 골라 참조를 넣습니다. 카탈로그 파일은 있는데
  항목이 없으면, 대신 새 샘플을 만들지 묻습니다. 카탈로그에 없는 시약·소모품·장비는 위의
  `새 {타입} ID 생성`·`직접 입력`으로 등록하면 됩니다.
- **`partbank에서 검색`** — partbank 연결을 설정해 둔 보관함에서만 보입니다.
  → [partbank에서 부품 가져오기](#partbank에서%20부품%20가져오기)

**제품 카탈로그**는 연구실에서 자주 쓰는 시약·소모품·장비, 또는 partbank에서 내려받은 부품 목록을
미리 적어 둔 읽기 전용 JSON입니다. 타입은 가리지 않습니다.
실험 폴더의 `resources/labsamples/`나 설정의 `전역 샘플 폴더`에 `{타입}_이름.json`(예:
`Reagent_Sigma.json`)으로 두면 됩니다. 이름은 공급사·용도 등 자유이고, 여러 개를 둘 수 있습니다.
`{타입}.json`은 대장이므로 카탈로그가 아닙니다(`DNA_Lib`이라는 타입을 만들었다면 그 대장
`DNA_Lib.json`을 `DNA`의 카탈로그로 읽지 않습니다).
설정의 `전역 샘플 폴더`를 바꾸고 설정 창을 닫으면, 옛 폴더에 남은 샘플(과 카탈로그 파일)을 새 폴더로
옮길지 묻습니다. 새 폴더에 같은 ID나 같은 이름의 파일이 있으면 그것만 옮기지 않고 알립니다.
옮기지 않으면 옛 폴더의 샘플은 보이지 않고, 설정을 되돌리면 다시 보입니다.
ID는 `{타입}-숫자` 형식이어야 합니다. 최소 예시:

```json
{
  "Reagent-1001": { "alias": "LB broth", "descriptions": ["Miller, 25 g/L"] },
  "Reagent-1002": { "alias": "Ampicillin", "descriptions": ["100 mg/mL stock"] }
}
```

ID는 `{타입}-숫자` 형식만 받습니다(예: `Reagent-1001`). 연구실 관리번호처럼 영문자가
섞인 번호는 ID 대신 **별칭**에 적으세요. 별칭·설명에 `|`를 써도 됩니다. 노트에는 `\|`로
들어가고(표 칸이 나뉘지 않도록), 읽기 화면과 대장에는 `|`로 보입니다.
**별칭에는 `;`와 `:`, 설명에는 `;`를 쓸 수 없습니다.** 노트에서 ID·별칭·설명을 가르는
글자라, 쓰면 별칭이 잘려 읽히기 때문입니다. 입력 창이 이유와 함께 막으니 `1:10` 대신
`1-10`이나 `1/10`처럼 적으세요. 별칭에는 `#`·`[[`·`]]`·`*`·`_`·`` ` ``도 쓸 수 없습니다(마크다운이 태그·링크·
강조·코드로 읽음). 특히 `_`는 옆에 한글이 붙으면(`대장균_형질전환`) 읽기 화면에서 그 사이가 기울임으로
바뀌고 `_`가 사라집니다. `-`나 `/`로 바꿔 쓰세요. 이미 그런 별칭으로 등록된 샘플은 그대로 두지만, 이미
기울임으로 보이는 별칭은 플러그인이 되돌릴 수 없으니 샘플 뷰의 `샘플 편집`으로 별칭을 바꾸세요. 이전 버전에서 이미 `;`·`:`가 든 별칭을 만들었다면 샘플 뷰의
`샘플 편집`으로 별칭을 바꾸세요. 옛 별칭을 쓴 노트의 참조·정의도 함께 고칠 수 있습니다
(`직접 입력`으로 같은 ID를 다시 넣는 방법은 노트의 옛 참조를 고치지 않습니다).

설정에서 추가한 **사용자 정의 타입**도 같은 방식으로 씁니다. 한글 타입(`배지`)이면 `@배지`로
자동완성됩니다. 타입 이름에는 글자·숫자·`_`만 쓰세요. 공백이나 `-`가 든 이름은 자동완성되지
않아서 설정 입력칸이 저장하지 않고 `Cell_Line`처럼 바꿀 이름을 알려 줍니다. `_`는 영문자·숫자
사이에서만 쓸 수 있습니다(`Cell_Line`). 한글처럼 다른 글자 옆에 두면 읽기 화면에서 이름이
기울임으로 보이므로, 이런 이름도 저장하지 않고 붙여 쓴 이름(`무세포_용해물` → `무세포용해물`)을
알려 줍니다(이전 버전에서 이미 저장한 이름은 샘플 파일이 끊기지 않도록 남겨 두고 경고만
표시합니다).
입력칸을 고치면 샘플 뷰가 바로 새 목록으로 바뀝니다. 목록에서 타입을 **지우면** 그 타입의 샘플은
샘플 뷰·자동완성에 보이지 않게 됩니다(파일은 그대로 남음). 그래서 설정 창을 닫을 때 지운 타입의
샘플이 전역 샘플 폴더나 실험의 `resources/labsamples/{타입}.json`에 남아 있으면 타입별 개수를
보여 주고 목록에 다시 넣을지 묻습니다. `다시 넣기`를 누르면 그 타입을 목록에 되돌립니다.

보관함 최상위 노트(예: `Welcome.md`)에서 샘플을 만들면, 직전에 연 실험과 상관없이 **Global
샘플**로 저장되고 그렇게 알려 줍니다(전역 샘플 폴더를 바꿔도 같음).

실험 README 머리말에 `sample_tracking: 'no'`를 두면 **그 실험의 노트에서만** 자동완성·하이라이트·
저장 시 대장 기록·샘플 가져오기 제안이 꺼집니다. 다른 실험과 샘플 뷰는 영향을 받지 않습니다.
이미 열려 있는 읽기 화면은 노트를 다시 열면 반영됩니다.

실험 노트(`.labnote.md`)에서 대장에 없는 ID를 참조하면 그 ID에 **빨간 물결 밑줄**이 생기고, 마우스를
올리면 "시료 대장에 없는 시료"라고 나옵니다(편집·읽기 화면 모두). 대장에서 지웠거나 다른 실험으로 옮겼거나,
전역 샘플 폴더 설정을 바꿨거나, 정의 없이 참조만 적은 경우입니다. 그 노트에 `@타입;ID` 정의로 쓰거나 샘플
뷰에서 등록하면 사라집니다. 제품 카탈로그에 있는 ID는 대장에 없어도 정상으로 봅니다. 대장 JSON이 깨져서
(git 병합 충돌 표시 등) 읽지 못하면 밑줄을 긋지 않습니다.
참조 `ID;별칭`의 별칭을 노트에서 고쳐 대장의 별칭과 달라지면(예: 대장은 `COL-001`인데 노트는 `COL-001b`)
그 참조에 **주황 점선 밑줄**이 생기고, 마우스를 올리면 "대장의 별칭: COL-001"이 나옵니다. 노트에서 별칭만
고쳐서는 대장이 바뀌지 않으니, 별칭을 바꾸려면 샘플 뷰 우클릭 → `샘플 편집`으로 고치세요(옛 별칭을 쓴 노트도
함께 고칠지 묻습니다). 그 노트에서 `@타입;ID;별칭`으로 정의한 샘플은 저장할 때 대장에 들어가므로 표시하지 않습니다.

문법이 궁금하다면: 정의는 `@dna;DNA-1737000000000;별칭;설명`, 참조는 `DNA-1737000000000;별칭`
입니다. 별칭 없이 설명만 쓸 때는 `@dna;ID;;설명`처럼 자리를 비워 두세요.

같은 노트의 정의에서 설명을 고쳐 저장하면, 그 노트가 전에 넣었던 설명은 새 설명으로 바뀝니다(설명이
쌓이지 않음). 다른 노트에서 넣은 설명과 `샘플 편집`으로 넣은 설명은 그대로 남습니다.

참조 뒤의 별칭은 **보기용**입니다. 참조는 "이 노트에서 썼다"는 기록만 남기고, JSON에 있는
별칭·설명은 바꾸지 않습니다(참조 뒤에 이어 쓴 문장이 별칭으로 들어가지 않도록). 별칭·설명을
바꾸려면 샘플 뷰에서 `샘플 편집`을 쓰거나 `@` 정의를 쓰세요. `샘플 편집`으로 별칭을 바꾸면
옛 별칭을 쓴 참조·정의를 노트마다 개수와 함께 보여 주고, 확인하면 함께 고칩니다(열린 노트는
Ctrl+Z 한 번으로 되돌릴 수 있음). 옛 별칭과 정확히 같은 참조만 고치고 다르게 쓴 참조는 그대로
둡니다. 거절하면 그 노트들은 옛 별칭을 그대로 보여 주고, 옛 별칭으로 **정의**(`@타입;ID;옛 별칭`)한
노트를 저장하면 대장의 별칭이 옛 값으로 되돌아갈 수 있습니다.
별칭이 없던 샘플에 별칭을 새로 붙이면, `DNA-123`처럼 ID만 적힌 참조에 `;새 별칭`을 붙일지도 묻습니다.

본문에 `ID;별칭` 참조만 적는다고 새 샘플이 등록되지는 않습니다(없는 ID를 참조해도 대장에
생기지 않음). 새 샘플은 위 자동완성 메뉴(`새 {타입} ID 생성`·`직접 입력`·카탈로그 검색),
`@타입;ID;별칭;설명` 정의, 또는 샘플 뷰의 `샘플 추가`로만 만듭니다.

**저장하면 약 1초 뒤 JSON에 반영됩니다.** 단 `.labnote.md` 파일만 대상이라, 일반
`.md` 노트에 쓴 정의는 동기화되지 않습니다.

### 노트를 다른 실험으로 옮길 때

노트는 **자기 실험**의 `resources/labsamples/`에서 Local 샘플을 찾습니다. 그래서 노트를 탐색기에서
다른 실험 폴더로 옮기면, 그 노트가 쓰던 Local 샘플은 원래 실험에 남아 새 실험에서는 찾을 수 없게
됩니다. 이때 Obsidian의 링크 갱신 창이 닫힌 뒤 **"{새 실험}의 노트가 쓰는 로컬 시료 N개가 다른
실험의 대장에 남아 있어 노트에서 찾을 수 없습니다. {새 실험}(으)로 가져올까요?"** 창이 뜨고, 샘플마다
어떻게 가져올지 보여 줍니다. `시료 가져오기`를 누르면 가져옵니다.
아래 `복사`가 하나라도 있으면 버튼 대신 선택 창이 뜹니다. `시료 가져오기(복사한 시료는 앞으로 따로
고쳐집니다)`는 그대로 가져오고, `원래 실험에서도 쓰는 시료는 전역으로 옮기고 나머지는 가져오기`는 두
실험이 함께 쓰는 샘플을 Global로 옮깁니다(Global에 같은 ID가 있으면 대신 복사하고 알려 줌).

- **`{원래 실험}에서 옮김`** — 원래 실험의 다른 노트는 쓰지 않는 샘플입니다. 새 실험 대장으로 옮기고
  원래 대장에서 지웁니다.
- **`{원래 실험}에서 복사(그 실험의 다른 노트도 씀)`** — 원래 실험의 다른 노트도 쓰는 샘플입니다. 새 실험 대장에 복사하고, 원래 대장에는 남겨
  둡니다(옮긴 노트만 사용 기록에서 뺍니다).

새 실험이나 Global에 이미 같은 ID가 있으면 건너뜁니다. 거절했거나 창을 놓쳤다면, 나중에 새
실험의 노트에서 `Sync workflow checklist with folder`를 실행하면 같은 제안을 다시 받을 수 있습니다
(같은 `labnote` 폴더의 다른 실험 대장에서 찾습니다. 여러 실험에 같은 ID가 있으면 가져오지 않고
목록만 알려 줍니다). 노트를 실험 밖(보관함 최상위 등)으로 옮기는 경우는 받을 대장이 없어 묻지 않습니다.
설정에서 `샘플 추적`이 꺼져 있으면 이 확인도 하지 않습니다.
복사한 샘플을 `샘플 편집`으로 고치면 그 실험의 기록만 바뀌므로, 같은 ID가 다른 실험 대장에도 있으면
그 실험 이름을 알려 줍니다.

같은 실험 안에서 노트 이름을 바꾸거나 `Renumber workflows`로 번호를 다시 매기면, Local 대장의 사용
기록도 새 노트 이름을 따라갑니다.

### 샘플 뷰

리본의 시험관 아이콘 또는 `Open sample view`. 4단 트리입니다:

**Local / Global** → **타입** → **샘플 ID | 별칭** → **별칭·설명**

`Local`은 지금 열어 둔 노트가 속한 실험의 샘플, `Global`은 보관함 전체 공용입니다. 보관함
최상위 노트를 열면 그 노트의 로컬 샘플이 곧 Global 샘플이라, Local 칸에는 "실험 밖 노트는 아래
Global 샘플을 씁니다" 안내 한 줄만 보입니다. 이런 노트에서 `Open sample definition`으로 연 정의 창도
범위를 `global`로 보여 주고 이동 버튼은 내지 않습니다. 이미지·PDF처럼 노트가 아닌 파일을 열었을 때만
마지막으로 연 실험을 계속 보여 줍니다.
샘플을 우클릭하면 ID 복사, 참조 삽입, **사용처 보기**, 편집, 삭제, **Local ↔ Global 이동**, **타입 변경**을 할 수 있습니다.
partbank에서 가져온 시료에는 `partbank에서 보관 위치 갱신`·`partbank에서 열기`도 함께 나옵니다
(→ [partbank에서 부품 가져오기](#partbank에서%20부품%20가져오기)).
**사용처 보기**는 그 샘플을 참조하거나 정의한 노트를 보관함 경로 목록으로 보여 주고, 고르면 그 노트를
엽니다(Local은 그 실험, Global은 보관함 전체에서 찾음). Global 샘플이면 같은 ID의 Local 샘플이 있는
실험의 노트는 그 Local 샘플을 쓰므로 빼고 보여 줍니다. 쓰는 노트가 없으면 알림으로 알려 줍니다.
편집·삭제·이동·타입 변경은 정의 창(`Go to definition`, 또는 팔레트의 `Open sample definition`)에도 있어
마우스 없이 쓸 수 있습니다. `Open sample definition`은 커서가 샘플 참조 위면 그 샘플을, 아니면
`ID | 별칭 | 범위` 목록에서 검색해 고른 샘플을 엽니다(ID나 별칭으로 검색).
참조 위는 ID뿐 아니라 `ID;별칭`의 **별칭 위**(바로 뒤 포함)도 됩니다. 우클릭 `Go to definition`도 같습니다.
참조 뒤에 이어 쓴 문장(`DNA-123;sampleA for the assembly`)은 별칭으로 읽히므로, 그 문장 위에서도
DNA-123이 열립니다.

- **참조 삽입**은 커서 위치에 맞춰 들어갑니다. 커서가 머리말(frontmatter)이나 맨 위 제목 위에
  있으면 문서 끝(마지막 절)에, 제목 줄 위에 있으면 그 제목 바로 다음 줄에, `@타입;ID;…` 정의가
  있는 줄(줄 가운데 정의 포함) 위에 있으면 그 줄 다음 줄에, 다른 참조 위에 있으면 그 줄 끝에,
  그 밖에는 커서 자리에 넣습니다. 정의 줄 끝에 붙이면 정의의 설명으로 읽히기 때문입니다.
  **표 줄**에서는 표가 끊기지 않도록 칸 안에 넣습니다. 커서가 참조나 정의 위에 있으면 그 바로
  앞에, 아니면 커서 자리에 넣습니다(맨 바깥 `|` 밖이면 안쪽으로 옮김).
- **삭제는 본문에서 쓰는 중이면 막힙니다.** 어느 노트에서 쓰는지 보관함 기준 전체 경로로 알려 주니, 본문에서 먼저 지운 뒤
  다시 삭제하세요(Local은 그 실험 폴더, Global은 보관함 전체를 확인). 노트의 기록은 남기고 다 쓴 시료로만
  보이게 하려면 대신 **`폐기로 표시`**를 쓰세요. 폐기된 샘플은 샘플 뷰에서 흐리게 `(폐기)`로, 자동완성에서는
  목록 맨 아래에 `(폐기)`로 보입니다. `샘플 편집`으로 별칭·설명·보관 위치를 고쳐도 폐기 표시는 남고,
  샘플 정의 창에 폐기한 날이 보입니다. `폐기 표시 해제`로 되돌립니다.
- **`이 실험의 시료 목록 삽입`**(명령 팔레트)은 이 실험의 Local 샘플 전부와 본문이 참조하는 Global 샘플을
  ID·별칭·설명(첫 설명)·보관 위치·범위·폐기 열의 표로 커서 위치에 넣고, 커서는 표 아래로 옮깁니다.
  표 칸 안에 커서가 있을 때 실행하면 그 표 아래에 넣습니다. CSV가 필요하면 그다음 `Export tables to CSV`를 쓰세요.
  이 실험의 노트가 참조하지만 어느 대장(Local·Global·제품 카탈로그)에도 없는 시료는 표에 넣지 않고, 완료 알림에
  그 참조(`ID;별칭`)를 적어 줍니다. 샘플 뷰에서 등록한 뒤 다시 실행하세요.
- 실험 밖 노트를 열면 Local과 Global이 같은 폴더라 `로컬로 이동` 메뉴가 보이지 않습니다. Global 샘플을
  어느 실험으로 옮기려면 그 실험의 노트를 연 뒤 실행하세요.
- 여러 실험에서 함께 쓰는 샘플은 **Local ↔ Global 이동**으로 Global에 두세요. Local 참조를 다른
  실험으로 복사하면 그 실험에서는 정의를 찾지 못합니다.
- **Global → Local로 옮길 때** 그 실험 밖의 노트가 이 샘플을 쓰고 있으면, 그 노트 경로를 보여
  주고 그래도 옮길지 묻습니다. 옮기면 그 노트에서는 정의를 찾지 못합니다.
- **타입 변경**은 새 타입을 고르면 ID 접두사를 바꾸고(`RNA-12` → `DNA-12`, 이미 있는 ID면 새 번호)
  기록을 `{새 타입}.json`으로 옮깁니다. 그 샘플을 쓰는 노트(Local은 그 실험, Global은 보관함 전체)의
  참조와 `@타입;ID` 정의도 함께 바꾸며, 바뀔 노트 목록을 보여 주고 한 번 확인받습니다. 거절하면
  아무것도 바뀌지 않습니다. Ctrl+Z로는 노트만 되돌아가고 샘플 기록은 그대로이니, 되돌리려면 타입 변경을
  다시 하세요.

### partbank에서 부품 가져오기

[partbank](https://partbank.kbiofoundry.kr)에 등록된 부품·디바이스·플라스미드·프라이머·분자·균주를
**시료로 등록**하고, **보관 위치**를 읽어 오고, **partbank 화면을 열 수 있습니다.** 쓰려면 먼저
플러그인 설정의 `partbank` 절에서 연결을 하나 이상 설정하세요. 설정 전에는 아래 메뉴와 명령이
보이지 않으므로, partbank를 쓰지 않는 보관함은 지금까지와 똑같습니다.

**연결 설정** — 연결은 두 가지입니다.

- **partbank 서버** — 연구실 서버(기본 `https://partbank.kbiofoundry.kr`). 링크가 팀 전체에서
  통하므로 **함께 쓰는 보관함이면 이쪽**을 쓰세요.
- **partbank 데스크톱 앱** — 이 PC에서 도는 앱(기본 `http://127.0.0.1:47830`). 데스크톱 앱으로 만든
  링크는 **그 PC에서만** 뜻이 있어, 다른 사람에게는 보관 위치 갱신과 열기가 되지 않습니다.
  휴대폰·태블릿에서는 이 연결이 아예 보이지 않습니다.

각 연결에 주소와 **API 키**를 적고 `연결 확인`을 누르면 계정 이름이 나옵니다. 키는 partbank의
Profile → API Keys에서 발급하며(최대 365일), **보관함이 아니라 이 PC에만** 저장되므로 PC마다 한
번씩 적어야 합니다. 보관함을 함께 쓰는 사람에게 키가 넘어가지 않습니다. 둘 다 설정하면 `검색할 연결`에서
자동완성 검색과 카탈로그 내려받기가 어느 쪽을 쓸지 고릅니다(기본 서버). 서버 주소가 `https://`가 아니면
키가 그대로 오간다고 경고합니다.

**검색해서 등록하기** — 본문에서 `@dna`, `@plasmid`, `@primer`처럼 치면 자동완성 맨 아래에
**`partbank에서 검색`**이 생깁니다. `@sample`에서도 보이며, 고르면 검색 창이 열립니다
(`;` 뒤에 쳐 둔 글자는 검색어로 미리 채워집니다). 두 글자 이상 치면 잠깐 멈춘 뒤 검색하고, 줄마다
이름·KID·종류와 `내 것`/`공유됨`/`공개`를 보여 줍니다. 고르면 상세와 보관 위치까지 읽어 시료로
등록하고 본문에 `ID;별칭`을 넣습니다.

- **친 타입마다 찾는 종류가 다릅니다.** `@dna`는 부품·디바이스·분자, `@plasmid`는 플라스미드,
  `@primer`는 프라이머, `@protein`·`@reagent`·`@rna`는 분자만, 균주 타입은 균주만, `@sample`은 전부
  찾습니다. 그래서 sfGFP 같은 부품은 `@protein`에서 나오지 않으니 `@dna`나 `@sample`에서 찾으세요.
  `partbank에서 검색` 항목의 설명과 결과가 없을 때의 안내에 찾은 종류가 나옵니다.
- 시료 타입은 **친 타입이 이깁니다.** `@sample`처럼 정해지지 않았을 때만 partbank 종류로 정합니다
  (부품·디바이스 → `DNA`, 플라스미드 → `Plasmid`, 프라이머 → `Primer`, 분자는 `protein`·`enzyme` →
  `Protein`, `rna` → `RNA`, `dna` → `DNA`, 나머지 → `Reagent`).
- **균주**는 내장 타입이 없어 사용자 정의 타입 `Strain`을 쓰며, 없으면 추가할지 묻습니다. 거절하면
  그 균주는 등록하지 않습니다.
- 등록되는 곳은 다른 샘플과 같습니다(실험 안이면 그 실험의 Local, 실험 밖이면 Global).
  **이미 같은 partbank 항목을 등록해 두었으면** 새로 만들지 않고 그 ID를 넣습니다(이 실험 → Global →
  제품 카탈로그 순으로 찾습니다). KID는 시료 ID가 아니라 연결 정보로 남고, 샘플 정의 창에 보입니다.

**보관 위치 갱신** — 샘플 뷰에서 우클릭하거나 샘플 정의 창에서 **`partbank에서 보관 위치 갱신`**을
누르면 `저장고 / 상자 / 칸` 형식으로 읽어 와 바뀔 때 한 번 확인한 뒤 `보관 위치`에 저장합니다.
partbank에 보이는 재고가 없으면 묻지 않고 지금 위치를 그대로 둡니다(지우려면 `샘플 편집`에서 위치를 비우세요).
연결된 시료를 한꺼번에 갱신하려면 명령 팔레트의 **`partbank에서 보관 위치 일괄 갱신`**을 쓰세요
(바뀌는 것만 `옛 위치 → 새 위치`로 보여 주고, 빈 값이 되는 항목은 손으로 적은 위치를 지우지 않도록
기본 체크 해제입니다). 저장된 값이라 다음부터는 오프라인에서도, 시료 목록 표와 검색에서도 그대로 보입니다.
partbank는 **요청한 계정에게 보이는 재고만** 주므로, 같은 보관함이라도 누가 갱신했느냐에 따라 값이
다를 수 있습니다.

**partbank에서 열기** — 같은 두 자리에 있습니다. 서버 연결이면 브라우저로, 데스크톱 연결이면
데스크톱 앱으로 그 항목을 엽니다(앱이 꺼져 있으면 앱이 켜집니다). 다른 PC의 앱에 연결된 시료는
열 수 없다고 알려 줍니다.

**카탈로그 내려받기** — 명령 팔레트의 **`partbank 카탈로그 내려받기`**는 기본 연결에서 **내 workspace
항목**을 받아 전역 샘플 폴더에 `{타입}_partbank-web.json`(데스크톱이면 `-desktop`)으로
씁니다. 이러면 검색 없이도 자동완성의 `{타입} 카탈로그 검색`에서 고를 수 있습니다. 워크플로 카탈로그를
맞추는 `Update catalogs`와는 다른 기능입니다. 다시 받아도 같은 품목은 **시료 ID를 그대로** 쓰고 KID
순으로 정렬해 쓰므로 git diff가 작습니다. 전역 샘플 폴더가 비어 있으면 알리고 멈춥니다. 남이 그룹에만
공유한 항목은 카탈로그에 들어오지 않으니, 그런 항목은 위의 `partbank에서 검색`으로 등록하세요.

**partbank에서 보내기** — partbank의 상세 화면에서 `labnoteo로 보내기`를 누르면 Obsidian이 떠서
그 항목을 등록할지 묻습니다(등록할 곳도 그 자리에서 Global로 바꿀 수 있습니다). Global을 골라도 이
실험에 같은 항목이 이미 등록돼 있으면 새로 만들지 않고 그 시료를 쓰며, 어디에 있는 시료를 썼는지 알려 줍니다.
설정에 없는 주소의 링크는 받지 않습니다. 등록한 뒤 노트가 열려 있으면 커서 자리에 `ID;별칭`을 넣을지 묻고, 아니면
클립보드에 복사합니다.

## AI 도우미

Obsidian 안에서 쓰는 보조 기능입니다 (커밋·이슈·Wiki를 다루는 외부 AI 에이전트와는
별개입니다).

| 명령 | 읽는 것 | 쓰는 곳 |
| --- | --- | --- |
| `AI: Draft Method section` | 지금 노트(유닛 오퍼레이션 안이면 그 블록) | 유닛 오퍼레이션 안이면 **그 `#### Method` 절**을 초안으로 채움(이미 쓴 내용이 있으면 먼저 물어봄). 밖이면 노트의 유닛 오퍼레이션 중 **어느 것의 Method에 넣을지** 고름. 유닛 오퍼레이션이 없는 노트에서는 모델이 붙인 머리말·제목 줄을 걸러 **커서가 있는 줄 다음**에 삽입 |
| `AI: Summarize results` | 지금 노트 전체(선택 영역이 아님). 템플릿 문구 줄과 앞서 넣은 AI 요약 콜아웃은 빼고 보냄 | **커서가 있는 줄 다음**에 요약을 `> [!note] AI 요약 (모델, 날짜)` 콜아웃으로 삽입. 커서가 머리말(frontmatter) 안이나 첫 제목 위에 있으면 **문서 끝**(보통 `Conclusions and Discussion` 절)에 붙임. 아직 결과가 없으면(워크플로 노트의 `Results & Discussions`·`QC Metrics`·`Discussion`·`Conclusions and Discussion`이 비었거나 템플릿 문구뿐이고, 직접 만든 절도 없을 때) 모델에 묻지 않고 "아직 요약할 결과가 없습니다"로 멈춥니다 |
| `AI: Extract sample definitions` | 지금 노트 | **본문에는 넣지 않고** 샘플 JSON에만 등록 — 결과는 샘플 뷰에서 확인하고, 본문에 쓸 참조는 직접 넣어야 합니다. 알 수 없는 타입은 건너뛰고, `{타입}-숫자` 형식이 아닌 ID는 새로 만듭니다. 본문에 적은 보관 위치(예: `보관: 4도 냉장고 1칸`)는 샘플의 **보관 위치** 칸에 넣고, 위치 없이 만든 샘플이 있으면 몇 개인지 알려 줍니다. 이미 대장에 있는 ID, 같은 타입·같은 별칭의 샘플, 별칭이 양쪽 다 없으면 같은 타입·같은 설명의 샘플, 노트에 이미 참조로 있는 ID는 건너뛰고 "새로 N개, 건너뜀 M개"로 알려 줍니다 |
| `AI: Ask assistant (uses tools)` | 입력한 목표 + 지금 노트(앞부분) | 도구로 보관함을 수정. **쓰기 전에 대상 경로를 보여주고 확인을 받습니다.** 절 내용을 바꿀 때는 지워질 줄 수도 함께 보여 줍니다. 마지막 답변은 **창으로 보여 주고 노트에는 넣지 않습니다** — `노트에 넣기`를 누르면 커서가 있는 줄 다음(커서가 머리말 안이나 첫 제목 위면 문서 끝)에 들어가고, `복사`로 가져갈 수도 있습니다. 그사이 다른 노트를 열었으면 넣지 않습니다. 답도 없고 도구도 쓰지 않았으면 "요청한 일이 쓸 수 있는 도구 밖일 수 있습니다"라고 알립니다(예: 실험 상태 변경은 도구가 없음). 끝 알림은 "AI 도구 호출: 변경 1건, 조회 2건, 거절 1건"처럼 실제로 바꾼 것과 거절·실패한 것을 따로 세고, 아무것도 바뀌지 않았으면 "보관함은 바뀌지 않았습니다"라고 알려 줍니다 |

모델이 답 없이 끝나면(생각만 하고 답을 내지 않는 thinking 모델 포함) 어느 AI 명령이든 "모델이 답을 주지
않았습니다"라고 알려 줍니다. 다시 시도하거나 다른 모델을 고르세요.

`AI: Draft Method section`과 `AI: Summarize results`도 응답이 올 때 **시작한 노트가 아직 열려 있을
때만** 넣고, "요약을 …에 넣었습니다"처럼 알려 줍니다. 기다리는 사이 같은 탭에서 다른 노트를 열었으면
그 노트는 건드리지 않고 답변 창을 띄웁니다. 원래 노트로 돌아와 `노트에 넣기`를 누르거나 `복사`로
가져가세요. 기다리는 사이 **노트 이름만 바뀐 경우**는 같은 노트이므로 그대로 넣습니다. 두 명령은 노트가 영어로 쓰여 있어도 Obsidian 화면 언어(한국어 화면이면 한국어)로 답하도록
모델에 요청합니다. 시료 ID·단위·숫자는 노트에 적힌 그대로 둡니다.

**설정 위치**: 설정 → 커뮤니티 플러그인 → **Labnote Assistant** → `AI provider` →
**Provider**. 기본값은 `Disabled`라 그대로 두면 AI 명령이 동작하지 않습니다.
`Ollama`(로컬) 또는 `OpenAI-compatible`을 고르고 엔드포인트·모델명을 채우세요.
엔드포인트를 `localhost:11434`처럼 `http://` 없이 적으면 접속할 때 `http://`를 붙입니다.
API 키는 OpenAI 계열에만 전송되며 Ollama로는 절대 나가지 않습니다.

## 출력본 스캔 붙이기

워크플로 노트를 **기록지로 출력**해 실험실에서 손으로 적고, 사진이나 스캔을 PC로 보내면 종이의 QR을
읽어 **원래 노트의 그 유닛 오퍼레이션 아래에** 붙입니다. 데스크톱 Obsidian에서만 됩니다.

1. **출력** — 워크플로 노트에서 명령 팔레트 → `Print experiment worksheet`(실험 기록지 출력). 실험실
   유닛 오퍼레이션이 미리 골라져 있고, 페이지마다 두 모서리에 QR이 찍힙니다. 인쇄 창이 안 뜨면
   `브라우저에서 열기`를 누르세요. 노트에는 고유 ID(`labnote_id: LN-…`)가 생깁니다.
2. **보내기** — 다 적은 기록지를 휴대폰으로 찍거나 복합기로 스캔(PDF·JPEG)해서
   - 설정 → Labnote Assistant → **바코드와 스캔** → `스캔 폴더`에 지정한 PC 폴더(Google Drive 전용
     폴더, 카카오톡 받은 파일, 복합기 폴더 등)에 넣거나 — 30초마다 확인합니다 —
   - 명령 팔레트 → `Import scanned pages`(스캔 가져오기) 창에 끌어다 놓습니다(zip·여러 쪽 PDF도 됨).
3. **확인** — "N쪽 붙임" 알림의 `자세히`나 결과 창에서 `노트 열기`·`되돌리기`를 고릅니다. 붙은
   이미지는 실험의 `images/scans/`에 저장되고, 노트에는 `#### Worksheet scans` 절이 생깁니다.
   스캔은 썸네일로 들어가며 설명 끝의 `원본 보기`로 크게 봅니다(폭은 설정 → **노트에 보이는
   스캔 폭**에서 변경). 결과 창은 `노트 › [UHW290 이름] 별칭`처럼 붙은 블록까지 보여 줍니다.
   QR에는 블록 제목(공정 이름과 별칭)의 지문이 들어 있어, 출력한 뒤 위쪽 블록을 지우거나 순서를
   바꿔도 같은 ID의 다른 블록에 붙지 않습니다. 블록 위치가 바뀌었거나 0.123.0 이전에 출력한
   종이면 맞는 블록에 붙었는지 확인하라고 알립니다. 출력한 뒤 별칭을 고친 블록은 짐작해서 붙이지
   않고 미인식으로 보냅니다.
4. **못 읽은 페이지** — 명령 팔레트 → `Assign unmatched scans`(미인식 스캔 할당)에서 노트와 유닛
   오퍼레이션을 골라 붙입니다. 출력일을 모르면 비워 두세요. 캡션에 출력일 없이 가져온 날만 적힙니다.

- 스캔 폴더는 **PC 한 대에서만** 지정하세요(PC마다 따로 저장됨).
- 노트의 `labnote_id` 줄과 `#### Worksheet scans` 절(안의 `<!-- labnoteo-scan … -->` 주석 포함)은
  지우거나 다른 노트로 복사하지 마세요. 스캔을 찾아 붙이고 되돌리는 데 씁니다. `labnote_id` 줄이
  지워져도 `Worksheet scans` 절의 스캔 이미지 이름에 옛 ID가 남아 있으면, 새 ID를 만들기 전에 그 ID를
  되살릴지 묻습니다. 되살려야 이미 출력한 기록지의 QR이 이 노트를 다시 찾습니다. `ID 되살리기`,
  `새 ID 발급`, `취소` 중에서 고르며, 취소하거나 창을 닫으면 노트는 그대로이고 하던 일(출력, 스캔 할당)도
  멈춥니다. 다음에 다시 묻습니다.
- 아이폰은 **설정 → 카메라 → 포맷 → 높은 호환성**으로 두세요(HEIC 사진은 열지 못함).

입력 경로별 자세한 방법(Google Drive·카카오톡·OneDrive·이메일·복합기·Slack)과 문제 해결은
[출력본 스캔 가이드](https://github.com/sblabkribb/labnoteo/blob/main/docs/SCAN.md)를 보세요.

## 자주 겪는 문제

**사진을 넣었는데 노트에 안 붙어요**
- 결과 창이나 알림의 `자세히`에 이유가 나옵니다. QR을 못 읽은 페이지는 `Assign unmatched scans`로 직접 붙이세요.
- 스캔 폴더는 그 PC에서 지정했나요? 지정하기 **전에** 있던 파일은 설정의 `기존 파일도 처리`를 눌러야 처리됩니다.
- 아이폰 HEIC나 복합기 TIFF는 열지 못합니다. JPEG·PDF로 보내세요.
- "여러 노트가 같은 ID …을(를) 쓰고 있습니다"는 노트를 파일 탐색기나 git으로 복사해 ID까지 복사된 것입니다. 복사본에서 명령 팔레트 → `Assign note ID`로 새 ID를 받으세요.

**push했는데 이슈가 안 생겨요**
- 먼저 보관함이 GitHub 저장소와 연결된 git 저장소인지 확인하세요(관리자 설정 완료 여부). 보관함 폴더에 `.git`이 없으면 push 자체가 되지 않습니다. 이때 플러그인은 논의 표시나 이슈 마커를 넣을 때 "아직 git 저장소가 아니라 이슈가 생성되지 않습니다"라고 알려 줍니다. `.labnoteo/SETUP.md`의 저장소 연결을 마치세요.
- 노트에 `@issue` 마커, 논의 표시(`discuss: true`), 또는 `status: needs-review` 중 하나가 있는지 확인하세요 — 이 신호가 있어야 이슈가 열립니다. 본문에 "논의 필요"라고 적은 것만으로는 열리지 않습니다.
- GitHub 저장소의 **Actions 탭**에서 `experiment-issues` 워크플로우가 실행됐는지 확인하세요.

**Actions 탭에 실행 기록 자체가 없어요**
- 이 워크플로우들은 **`labnote/` 아래 파일이 바뀐 push에서만** 돕니다. 설정 파일이나 Wiki 초안만 고쳐 push하면 아무것도 실행되지 않습니다.
- 지금 당장 돌리고 싶다면 **Actions 탭 → `experiment-issues` → `Run workflow`** 를 누르세요. 수동 실행은 바뀐 파일이 아니라 **모든 실험 폴더**를 훑으므로, 그동안 처리되지 않고 남아 있던 마커가 한꺼번에 이슈로 열립니다.

**플러그인은 어떻게 업데이트하나요?**
- BRAT가 앱을 켤 때 자동으로 최신 릴리스를 확인·설치합니다(설정 → `Obsidian42 - BRAT`에서 자동 갱신을 끌 수 있음).
- 지금 바로 받으려면 명령 팔레트 → `Check for updates to all beta plugins and UPDATE`.
- 업데이트 뒤 Obsidian을 켜면 직접 고치지 않은 자동화 파일(이 문서, `.labnoteo/` 스크립트 등)이 새 버전으로 자동 갱신되고 "자동화 파일 N개를 이 플러그인 버전에 맞게 갱신했습니다" 알림이 뜹니다. 설치 기록(`.labnoteo/installed.json`)이 없는 오래된 보관함도, 이전 버전이 만든 그대로인 파일은 자동으로 갱신됩니다.
- "설치 후 내용이 바뀌었거나 이전 버전 기록으로 확인할 수 없어 그대로 두었습니다" 알림이 뜨면 명령 팔레트 → `Setup research automation`을 실행하세요. 파일마다 덮어쓸지 묻습니다. 이 알림과 "보관함에 없습니다" 알림은 새 버전마다 한 번만 뜹니다.
- 서버 자동화 동작까지 최신으로 맞추려면 아래 항목을 보세요.

**플러그인을 업데이트했는데 서버 동작이 예전 그대로예요**
- GitHub Actions는 **저장소에 커밋된** `.labnoteo/scripts/*.mjs`를 실행합니다. 보관함의 스크립트가 갱신되어도 커밋·push 전에는 서버가 바뀌지 않습니다.
- 갱신된 `.labnoteo/`(`installed.json` 포함)를 **커밋하고 push**하세요. 갱신 알림을 받지 못했다면 먼저 명령 팔레트 → `Setup research automation`을 실행하세요.

**마커를 넣었는데 이슈가 안 생겨요**
- 마커가 색으로 강조되어 있나요? 강조되지 않으면 형식이 잘못된 것입니다. 형식은 `@issue;<ID>;<주제문장>`이고, 세 부분이 모두 있어야 합니다.
- 손으로 `@issue;논의 필요`처럼 ID 없이 쓰면 무시됩니다. 명령 팔레트 → `Insert issue marker`로 넣으면 ID가 자동으로 붙습니다.
- **Actions 탭**의 `validate`가 실패했다면 어느 줄이 잘못됐는지 알려줍니다.
- 이미 닫은 마커 이슈는 다시 열리지 않습니다. 새 논의는 새 마커로 시작하세요.

**"duplicate marker ID" 경고가 떠요**
- 마커가 있는 줄을 복사해 같은 실험 폴더의 다른 노트에 붙여넣은 것입니다. ID가 겹치면 두 질문이 **한 이슈로 합쳐집니다.**
- 복사된 쪽의 마커를 지우고 `Insert issue marker`로 새로 넣으세요.

**`Insert unit operation`이 "워크플로 파일에서 실행해주세요"라고만 해요**
- README나 일반 노트에서는 동작하지 않습니다. `###_이름.labnote.md` 형식의 워크플로 노트를 열고 실행하세요.
- 워크플로 파일인데도 거부된다면 파일명이 `###_`로 시작하는지, `.labnote.md`로 끝나는지 확인하세요.

**워크플로를 다른 실험으로 옮겼는데 체크리스트에 안 보여요**
- 폴더 간 이동은 자동 등록되지 않습니다. 대상 실험의 README나 실험 폴더를 **우클릭 → `Sync workflow checklist with folder`** 로 등록하세요(명령 팔레트에도 있음).
- 원래 실험에서도 같은 명령을 실행하면 옮겨 간 항목을 확인 후 지웁니다.
- `Insert workflow`를 쓰면 옮긴 파일이 등록되지 않고 카탈로그에서 고른 빈 워크플로 노트가 새로 생깁니다.

**커밋이 거부돼요 (대용량 파일)**
- 50MB 초과 파일은 커밋이 차단됩니다. 파일을 `raw-data/` 등 Git 밖 보관 위치로 옮기고, 노트에는 경로/ID만 남기세요.
- `git commit --no-verify`로 우회하지 마세요 — 서버 검증에서 다시 걸립니다.

**AI 명령이 응답이 없어요**
- 설정 → Labnote Assistant → **Provider**가 `Disabled`가 아닌지(Ollama/OpenAI) 확인하고, 엔드포인트·모델명을 설정하세요.
- 실패 알림이 고칠 설정을 알려 줍니다. "연결할 수 없습니다"면 Ollama가 켜져 있는지와 엔드포인트, "API 키가 없거나
  잘못"이면 API 키, "모델 …을(를) 찾을 수 없습니다"면 모델 이름(Ollama는 `ollama pull`로 받았는지),
  "(404)"면 엔드포인트에 `/v1`·`/api` 같은 경로를 붙이지 않았는지, "http:// 또는 https:// 주소가 아닙니다"면
  엔드포인트를 `http://localhost:11434`처럼 적었는지 보세요.
- 오래 기다린 끝에 "모델이 답을 주지 않았습니다(생각만 하고 끝남)"가 뜨면, thinking 모델이 답 대신 생각만
  돌려준 것입니다. 다시 시도하거나 다른 모델을 고르세요.

**노트 검증이 실패해요 (Actions의 validate)**
- `status` 값이 허용 목록(`planned`, `in-progress`, `needs-review`, `completed`, `failed`, `discontinued`, `needs-repeat`)에 있는지, 실험 `id`와 마커 ID, 노트 ID(`labnote_id`)가 중복되지 않는지 확인하세요. 노트 ID가 겹치면 복사본에서 `Assign note ID`로 새 ID를 받으세요.

**Wiki가 갱신되지 않아요**
- Wiki 발행은 **`main` 브랜치에 들어갔을 때만** 일어납니다. 작업 브랜치에 `wiki-staging/`을 고쳐 push해도 발행되지 않습니다(이슈·검증과 다른 점입니다).
