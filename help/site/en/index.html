Labnote Assistant Help

Short clips of each feature of Labnote Assistant (labnoteo), a plugin for recording biofoundry-based synthetic biology experiments as Obsidian notes. The clips are recordings of the plugin itself, and the caption strip at the top of each one explains the steps.

Clips recorded with labnoteo 0.105.0.

This page does not repeat the detailed rules (folder naming, when CSVs are overwritten, …); it links to the README for them. The in-vault user guide (command palette → Open user guide) is in Korean.

Getting started

Installation

Turn off Restricted mode in Settings, install BRAT from Community plugins, then enter sblabkribb/labnoteo in BRAT's Add beta plugin. Once it is installed, workflow and sample icons appear in the left ribbon.

Step by step: Installation guide · 4. Install Labnote Assistant via BRAT

Setup research automation

Setup research automation installs the GitHub Actions, scripts and AI agent rules for note validation, Experiment ↔ Issue links and Wiki publishing into the vault. AGENTS.md and QUICKSTART.md appear in the explorer; dot folders such as .github/ and .labnoteo/ are hidden in Obsidian.

Finding commands

Commands live in Obsidian's command palette (Ctrl/Cmd+P). Type Labnote to list only this plugin's commands. Under a Korean UI each name shows as Korean (English), such as 실험 생성 (Create experiment), and the English name finds it too; an English UI shows the English name alone.

Right-click menus and dialogs show the UI language only. Some features are only on right-click menus; see Right-click only features.

5-minute walkthrough

Create an experiment

Command palette → Create experiment → enter a title. Below the box it counts the characters that go into the folder name, then creates and opens labnote/###_title/README.labnote.md. Fill in author in the front matter right away: workflows you create later take their experimenter from it.

Command reference · Create experiment (folder name rules)

Experiments in the workflow view

The workflow view, opened with the box icon in the ribbon, groups the vault's experiments under Experiments at the top. Filter them with Search experiments and switch between By status, By project (the README's project), By author (the README's author) and By discussion. By discussion puts the experiments flagged for discussion or with an @issue marker under Something to discuss. In a filtered list, an experiment whose status or discussion flag you change by right-click stays listed until you change the search, even if it no longer matches, so you can right-click it again to undo. Right-click a failed or needs-repeat experiment → Retry this experiment to create a retry linked to it (Retry an experiment).

The grouping switch is a system list box, so its open list does not show in the clip; the caption says which item is picked.

Change the status

Command palette → Change experiment status → pick a status. The list says what each status means. Run from any note of an experiment, it updates that experiment's README. You can also right-click an experiment in the workflow view and choose Change experiment status; the new status shows in the view's groups at once.

When you mark an experiment completed, it tells you if there are no workflows, unchecked workflows, workflow notes with an empty end_date, a discussion flag that is on or @issue markers left, and asks once more. With the discussion flag on, you choose whether to clear it or keep it.

Retry an experiment

In the workflow view, right-click a failed or needs-repeat experiment → Retry this experiment to create a planned experiment with the next number. The title is filled in from the original's and can be edited. The new README takes the original's author and project as they are, so it lands in the same By author and By project group, and its retry_of property links to the original README. Workflow notes are not copied.

Hover in the workflow view to see how the two experiments are linked; typing the original's number in the search keeps both. Duplicating a failed or needs-repeat experiment folder in the file explorer also asks whether to Mark as retry.

Command reference · Retry this experiment

Flag what needs discussion

Select the sentence you have a question about and run Insert issue marker to add an @issue;ISS-…;topic marker. To discuss the whole experiment, use Toggle discussion flag. A push then opens GitHub Issues (in a vault with research automation set up).

To commit and push, tell the AI agent connected through Copilot "commit and push today's work". Shortly after the push, the repository's Issues tab shows an Issue for each marker. These steps happen outside Obsidian, so they are shown as screenshots rather than clips.

Recording

Create a workflow

From the experiment README, Create workflow → search the catalog → enter an alias. The new workflow is added to the README checklist on its own.

Command reference · Create workflow (file name rules)

Rename and copy a workflow

Rename a workflow note in the file explorer and its label in the README checklist follows. Make a copy from the explorer's right-click menu and you are asked for the copy's alias; it gets the next number and is listed in the checklist.

Renumber workflows

Renumber workflows renumbers the workflows from 001 without gaps in the order of the README checklist, showing each change before it asks.

Sync the checklist with the folder

Workflows moved in from another experiment or copied are not listed on their own. Sync workflow checklist with folder lists the missing ones and shows labels that no longer match their file names as old label → new label before fixing them.

Right-click only features

README right-click → Insert workflow; right-click a catalog item in the workflow view → Insert unit operation; right-click a note in the file explorer → Export tables to CSV. These are easy to miss from the palette alone.

Insert a unit operation

With a workflow note open, Insert unit operation → pick the operation → alias. The table of contents at the top of the note is rebuilt in heading order.

Reorder unit operations

Drag a unit operation heading in Obsidian's Outline view and the TOC and --- separators are tidied for you.

README · Settings (Auto-sync unit operation TOC)

Insert dates

Insert date and Insert date and time put today's date and time at the cursor, also inside a table cell. In reading view they say to switch to the editing view. The 📅 icon at the end of a date line in a unit operation's #### Meta opens a date field.

The calendar popup is drawn by the operating system and does not show in recordings, so the clip changes the value in the field instead.

Export tables to CSV

Export tables to CSV saves each table of the note as note name.labnote_table1.csv next to it. To export a whole experiment at once, see Excel warning and the whole experiment as CSV.

Command reference · Export tables to CSV (when files are overwritten)

Excel warning and the whole experiment as CSV

Export all tables of this experiment to CSV exports the tables of every note directly in the experiment folder, starting with the README. It is also on the right-click menu of an experiment folder or its README in the file explorer. If CSV files would be overwritten, it asks once for all of them instead of note by note.

Double-click a CSV to open it in Excel and 1/2 becomes a date, 007 loses its leading zero and 2E4 becomes 20000. When a table has such cells, the completion notice names them and their columns for each CSV; open the file in Excel with Data → From Text/CSV and set those columns to Text. The CSV itself keeps what you wrote. It also names any CSV whose path is longer than Excel can open (218 characters). CSV files left without a matching note are listed, and you are asked whether to move them to the trash.

The notice goes away after a while, so the clip's caption points out what it says.

Working with samples

Refer to samples in the text

Type @DNA; while editing to open autocomplete. Pick Generate new DNA ID to register a new ID; only the reference goes into the text. Right-click in the text → Add sample works too.

Samples view

In the Samples view, opened with the test-tube icon in the ribbon, add, edit (including the storage location) and search samples; mark a used-up sample with Mark as discarded instead of deleting it.

Find and delete samples

The Search samples box at the top of the Samples view matches descriptions and storage locations as well as IDs and aliases: type freezer and only the samples kept in a freezer remain. It reads _, : and ; as -, so the name as written in a note finds the sample.

Right-click → Delete sample shows the alias, description and location and asks before deleting. A sample still used in the text is not deleted; the window says which notes use it, and to keep their record use Mark as discarded instead. When sample tracking is off, Open sample definition in the palette says whether the setting or the README's sample_tracking: 'no' turned it off.

Command reference · Sample view context menu

Definitions and usages

Right-click a reference in the text → Go to definition opens that sample's definition. In the Samples view, right-click → Show sample definition opens the same window. It shows the descriptions with the notes they came from, the partbank link, and the usages grouped by experiment; click a usage to open that note. In the Samples view, right-click → View usages lists each line that uses the sample with its note and section; pick one to open the note with the cursor on that reference.

Change type and move to Global

Fix a wrong type with Samples view right-click → Change type. After you confirm the list of notes it will change, the ID prefix in their references changes too. Keep samples shared by several experiments in Global with Move to Global.

This experiment's samples as a table

Insert sample list of this experiment inserts a table of the experiment's Local samples and the Global samples its notes refer to, with ID, alias, description, location, scope and discarded columns.

Custom sample types

Add a type such as Media under Settings → Labnote Assistant → Custom sample types and @Media autocompletes right away. Use letters, digits and _ only. A _ works between ASCII letters and digits (Cell_Line); next to other letters it turns the name italic in the reading view, so write those together (무세포용해물).

partbank parts as samples

Under partbank in Settings → Labnote Assistant, enter the address and API key of a partbank server (use this for a vault the team shares) or of the partbank desktop app on this PC, and press Test connection. The key is kept on this PC only, not in the vault, so it does not reach the people you share the vault with. The partbank menus and commands appear only after a connection is set up.

Type @DNA; in a note and the autocomplete ends with Search partbank. The search finds only your own items and those shared with your groups; the one you pick is registered as a sample with its details and storage location, and a reference goes into the text. An item you already registered is reused instead of added again. Refresh storage location from partbank, on the Samples view right-click menu and in the definition window, reads the location again, and Refresh storage locations from partbank in the palette updates the whole vault at once. Open in partbank opens the item in the browser or the desktop app, and copies the link to the clipboard if it cannot.

Lab notes that use samples taken from partbank are listed on that item's partbank page, visible only to you. What is sent is the vault name, the note path and title, the experiment folder name and the headings of the sections where the sample appears, never the note text. Clicking a note on the partbank page opens it in Obsidian at that section (obsidian://labnoteo-open). partbank's Send to labnoteo works the other way, bringing up Obsidian to register the item (obsidian://labnoteo-import). To stop sending usages, turn off Send note usages to partbank under partbank in settings; this also deletes what this PC sent from partbank.

The settings screen shows the account name, so the clip starts with the connection already made.

Printed worksheets and scans

Print a workflow note as an experiment worksheet, write on it at the bench, then send a photo or scan to your PC: the plugin reads the QR code on the paper and files the image under that unit operation in the original note. Everything runs inside Obsidian on your PC, with no server, on desktop Obsidian only.

Print a worksheet

In a workflow note, command palette → Print experiment worksheet. The QR icon at the top of the note (Show note barcode) shows the note ID and its QR code, and you can print from there too. In the print dialog, pick the unit operations (lab (HW) unit operations are already on), set the Paper size and press Print.

Each page carries the note ID's QR code in two corners. Method steps keep the numbers they have in the note, with indented lines under their step and pipe tables drawn as tables. An empty section is left as ruled writing space (Method and Results & Discussions get the most), and an empty Meta value prints as a blank. Print at 100% (actual size).

The print window is drawn by the operating system, so the clip stops at the print dialog. If no print window appears, use Open in browser to print from your system browser.

File scans in notes

Open the dialog with the scan icon in the ribbon or command palette → Import scanned pages, and drop in photos, PDFs or a zip. When it finishes, the Scan results dialog reports something like "1 page(s): 1 filed", with Open note and Undo for each page. In the note, the scan goes into #### Worksheet scans at the end of that unit operation as a 200px-wide thumbnail; Open full size at the end of its caption opens the original.

To skip the dragging, set a PC folder (a Google Drive folder, a scanner folder, KakaoTalk downloads, …) as the Scan folder under Settings → Barcode & scans. Choose Dedicated folder for a folder that holds only scans and Shared folder for one mixed with other files. Pages whose QR code could not be read are filed by hand with Assign unmatched scans.

Send scans through Slack

If you use Slack, you can send worksheet photos from your phone as a DM to your own Slack bot. Create a Slack app by pasting the manifest from the scan guide and copy its bot token (starting with xoxb-). Under Settings → Barcode & scans → Slack scans (optional), paste it into Slack bot token, choose Direct message to the bot and press Connect. Send the link code it shows, such as labnote-123456, to the bot as a DM, and the bot replies "Linked" in the thread.

After that, send photos as new messages in the conversation, not as replies in the thread. While Obsidian is running on this PC, it checks about every 90 seconds, adds a 👀 reaction and reports the result as a thread reply to that message. Link only one PC; to unlink, press Disconnect in the same place. These are Slack screens, so they are shown as screenshots rather than clips.

Building the Wiki

When an experiment wraps up, ask the AI agent to "summarize the objective facts this experiment established into wiki-staging". After you review the draft and merge it into main, it is published to the GitHub Wiki.

README · Research automation

AI assistant

Helpers that work inside Obsidian. The clips were recorded with a local Ollama qwen3.5:9b model, with the wait for each reply fast-forwarded. What the model writes varies with the model and the language.

AI provider settings

Under Settings → Labnote Assistant → AI provider, set Provider to Ollama or OpenAI-compatible and fill in the Ollama endpoint (or OpenAI endpoint) and Model. It is Disabled by default, and the AI commands do nothing until you change it.

Draft the Method

Run AI: Draft Method section inside a unit operation and it fills that block's #### Method section. The draft starts with the line AI draft (model, date) — review it, then delete this line; delete it once you have reviewed the draft.

Summarize results

AI: Summarize workflow results reads only the result sections of a workflow note and puts a > [!note] AI workflow results summary callout at the end of Conclusions and Discussion. In a note with no results written yet it stops instead of asking the model.

Summarize an experiment

Run AI: Summarize experiment results in an experiment README to gather the results of all its workflow notes in checklist order and put a summary at the end of the README's Summary and Discussion.

Extract sample definitions

AI: Extract sample definitions registers the samples the text mentions and reports how many were new and how many were skipped. Nothing goes into the text, so check the result in the Samples view.

Ask the assistant

Give AI: Ask assistant (uses tools) a goal and the model changes the vault with Labnote's tools, asking before each write; a change you allow goes into the note at once. If the model ends with an answer, it opens in a dialog and goes into the note only when you press Insert into note.

Other settings

  • Sample tracking and Global sample folder: Sample tracking under Settings → Labnote Assistant turns autocomplete, highlighting and registry sync on or off (reload to apply). After you change the Global sample folder and close settings, you are asked whether to move the samples in the old folder. README · Settings
  • MCP server: in the MCP server section of settings, Enable MCP server exposes Labnote's tools to an external MCP client. Copilot agents guide (Korean)
  • partbank connection: connecting, searching, storage locations and sending usages are under partbank parts as samples. To keep your workspace items at hand ahead of time, use Download partbank catalog.
  • The settings screen: from Obsidian 1.13, the settings search also finds this plugin's options. Number and folder fields are checked and saved when you leave the field or press Enter; a number out of range or a folder name Windows cannot create is refused with the reason. README · Settings
  • Moving a note to another experiment: when the moved note uses Local samples of its old experiment, you are asked whether to bring them along. Command reference · Moving to another folder

Troubleshooting

  • I pushed but no Issue opened: check that the vault is a git repository connected to GitHub, and that the note has an @issue marker, the discussion flag, or needs-review.
  • Insert unit operation refuses to run: open a ###_name.labnote.md workflow note, not the README, and run it there.
  • AI commands do nothing: check that Provider is not Disabled and that the endpoint and model name are right. A failure notice names the setting to fix.
