Labnote Assistant Help

Short clips of each feature of Labnote Assistant (labnoteo), a plugin for recording biofoundry-based synthetic biology experiments as Obsidian notes. The clips are recordings of the plugin itself, and the caption strip below each one explains the steps.

Clips recorded with labnoteo 0.105.0.

This page does not repeat the detailed rules (folder naming, when CSVs are overwritten, …); it links to the README for them. The in-vault user guide (command palette → Open user guide) is in Korean.

Getting started

Installation

Turn off Restricted mode in Settings, install BRAT from Community plugins, then enter sblabkribb/labnoteo in BRAT's Add beta plugin. Once it is installed, workflow and sample icons appear in the left ribbon.

Step by step: README · Installation

Overview

In under two minutes: create an experiment, add a workflow and a unit operation, refer to a sample in the text, and change the progress status. Each step has its own clip, linked below.

Finding commands

Commands live in Obsidian's command palette (Ctrl/Cmd+P). Type Labnote to list only this plugin's commands. Under a Korean UI each name shows as Korean (English), such as 실험 생성 (Create experiment), and the English name finds it too; an English UI shows the English name alone.

Right-click menus and dialogs show the UI language only. Some features are only on right-click menus; see Right-click only features.

5-minute walkthrough

Create an experiment

Command palette → Create experiment → enter a title. Below the box it counts the characters that go into the folder name, then creates and opens labnote/###_title/README.labnote.md. Fill in author in the front matter right away: workflows you create later take their experimenter from it.

README · Commands (folder name rules)

Change the status

Command palette → Change experiment status → pick a status. Run from any note of an experiment, it updates that experiment's README.

Experiments in the workflow view

The workflow view, opened with the box icon in the ribbon, groups the vault's experiments under Experiments at the top. Filter them with Search experiments and switch between By status and By project (the README's project). Right-click an experiment and choose Change experiment status to change it in place.

The grouping switch is a system list box, so its open list does not show in the clip; the caption says which item is picked.

Flag what needs discussion

Select the sentence you have a question about and run Insert issue marker to add an @issue;ISS-…;topic marker. To discuss the whole experiment, use Toggle discussion flag. A push then opens GitHub Issues (in a vault with research automation set up).

README · Research automation

Commit, push and check the Issues

To commit and push, tell the AI agent connected through Copilot "commit and push today's work". Shortly after the push, the repository's Issues tab shows an Issue for each marker. These steps happen outside Obsidian, so they are shown as screenshots rather than clips.

Building the Wiki

When an experiment wraps up, ask the AI agent to "summarize the objective facts this experiment established into wiki-staging". After you review the draft and merge it into main, it is published to the GitHub Wiki.

Recording

Create a workflow

From the experiment README, Create workflow → search the catalog → enter an alias. The new workflow is added to the README checklist on its own.

README · Commands (file name rules)

Rename and copy a workflow

Rename a workflow note in the file explorer and its label in the README checklist follows. Make a copy from the explorer's right-click menu and you are asked for the copy's alias; it gets the next number and is listed in the checklist.

Renumber workflows

Renumber workflows renumbers the workflows from 001 without gaps and updates the checklist.

Sync the checklist with the folder

Workflows moved in from another experiment or copied are not listed on their own. Sync workflow checklist with folder lists the missing ones and shows labels that no longer match their file names as old label → new label before fixing them.

Right-click only features

README right-click → Insert workflow; right-click a catalog item in the workflow view → Insert unit operation; right-click a note in the file explorer → Export tables to CSV. These are easy to miss from the palette alone.

Insert a unit operation

With a workflow note open, Insert unit operation → pick the operation → alias. The table of contents at the top of the note is rebuilt in heading order.

Reorder unit operations

Drag a unit operation heading in Obsidian's Outline view and the TOC and --- separators are tidied for you.

README · Settings (Auto-sync unit operation TOC)

Insert dates

Insert date and Insert date and time put today's date and time at the cursor. The 📅 icon at the end of a date line in a unit operation's #### Meta opens a date field.

The calendar popup is drawn by the operating system and does not show in recordings, so the clip changes the value in the field instead.

Export tables to CSV

Export tables to CSV saves each table of the note as note name.labnote_table1.csv next to it.

Working with samples

Refer to samples in the text

Type @DNA; while editing to open autocomplete. Pick Generate new DNA ID to register a new ID; only the reference goes into the text. Right-click in the text → Add sample works too.

Samples view

In the Samples view, opened with the test-tube icon in the ribbon, add, edit (including the storage location) and search samples; mark a used-up sample with Mark as discarded instead of deleting it.

Definitions and usages

Right-click a reference in the text → Go to definition opens that sample's definition. In the Samples view, right-click → View usages lists the notes that use the sample; pick one to open it.

Change type and move to Global

Fix a wrong type with Samples view right-click → Change type. After you confirm the list of notes it will change, the ID prefix in their references changes too. Keep samples shared by several experiments in Global with Move to Global.

This experiment's samples as a table

Insert sample list of this experiment inserts a table of the experiment's Local samples and the Global samples its notes refer to, with ID, alias, description, location, scope and discarded columns.

Custom sample types

Add a type such as Media under Settings → Labnote Assistant → Custom sample types and @Media autocompletes right away. Use letters, digits and _ only.

AI assistant

Helpers that work inside Obsidian. The clips were recorded with a local Ollama qwen3.5:9b model, with the wait for each reply fast-forwarded. What the model writes varies with the model and the language.

AI provider settings

Under Settings → Labnote Assistant → AI provider, set Provider to Ollama or OpenAI-compatible and fill in the Ollama endpoint (or OpenAI endpoint) and Model. It is Disabled by default, and the AI commands do nothing until you change it.

Draft the Method

Run AI: Draft Method section inside a unit operation and it fills that block's #### Method section.

Summarize results

AI: Summarize results reads the whole note and inserts a > [!note] AI summary callout after the cursor's line.

Extract sample definitions

AI: Extract sample definitions registers the samples the text mentions and reports how many were new and how many were skipped. Nothing goes into the text, so check the result in the Samples view.

Ask the assistant

Give AI: Ask assistant (uses tools) a goal and the model changes the vault with Labnote's tools, asking before each write; a change you allow goes into the note at once. If the model ends with an answer, it opens in a dialog and goes into the note only when you press Insert into note.

Research automation

Setup research automation

Setup research automation installs the GitHub Actions, scripts and AI agent rules for note validation, Experiment ↔ Issue links and Wiki publishing into the vault. AGENTS.md and QUICKSTART.md appear in the explorer; dot folders such as .github/ and .labnoteo/ are hidden in Obsidian.

README · Research automation

Other settings

  • Sample tracking and Global sample folder: Sample tracking under Settings → Labnote Assistant turns autocomplete, highlighting and registry sync on or off (reload to apply). After you change the Global sample folder and close settings, you are asked whether to move the samples in the old folder. README · Settings
  • MCP server: Enable MCP server exposes Labnote's tools to an external MCP client. Copilot agents guide (Korean)
  • Moving a note to another experiment: when the moved note uses Local samples of its old experiment, you are asked whether to bring them along. README · Commands

Troubleshooting

  • I pushed but no Issue opened: check that the vault is a git repository connected to GitHub, and that the note has an @issue marker, the discussion flag, or needs-review.
  • Insert unit operation refuses to run: open a ###_name.labnote.md workflow note, not the README, and run it there.
  • AI commands do nothing: check that Provider is not Disabled and that the endpoint and model name are right. A failure notice names the setting to fix.
